## 0. 가설 (한 문장)
**4h 시계열 모멘텀 부호 방향으로만, 1m 결정론적 S/R 밴드까지 되돌린 뒤 거부(rejection)가 확인될 때 진입하면, 같은 진입·SL·TP를 필터 없이 쓰는 대조군보다 비용 차감 후 트레이드당 순엣지가 높다.**
- **Arm A(주)**: 방향 필터 = 4h TSMOM 부호(VCB T1_v2와 같은 가족) + S/R 되돌림 진입.
- **Arm B(대조)**: 진입·SL·TP 규칙 동일, **방향 필터 없음**(양방향 모두 진입).
- A/B가 의미 있는 이유: 필터가 셋업의 약 절반(부호가 반대인 쪽)을 제거하므로 **진입 조건이 실질적으로 갈린다**(learnings의 "A/B는 진입조건이 갈려야 의미" 조건 충족). 두 암은 같은 후보 셋업 집합에서 서로 다른 부분집합을 취한다 — 중복 트레이드가 아니다.
- 보유 기대: 수 시간 · 하루 1~3회. **1m은 타이밍 스케일이지 신호 스케일이 아니다**(§1 비용 산식 참조).

## 1. S/R 레벨 정의 (결정론적 · 전부 config · `params_version = sr_v1`)
차트 판단·재량 금지. 아래 계산만으로 레벨 집합이 재현된다(스킬 strategy-modules §4 표의 "스윙 고/저"·"볼륨 프로파일" 두 가지만 쓴다).

| 항목 | 값(사전확약) |
|---|---|
| 스윙 레벨 스케일 | **15m 봉**(1m 집계) · fractal `k = 3`(좌우 각 3봉) |
| 스윙 레벨 확정 시각 | fractal k=3은 스윙 봉 **이후 3번째 15m 봉이 마감해야 확인된다** → 레벨은 그 마감 시각부터 사용(룩어헤드 차단) |
| 스윙 레벨 유효기간 | **확정 시각**부터 **48시간**(192개 15m 봉) 또는 **무효화**될 때까지 |
| 스윙 레벨 무효화 | 15m **종가**가 레벨 밖으로 `0.25 × ATR_15m(14)`를 초과해 마감 |
| 볼륨 프로파일 창 | 직전 **24시간**(1440개 1m 봉) 롤링 · 매 1m 봉 마감마다 갱신 |
| VP bin 크기 | **10.0 USDT**(BTCUSDT tick 0.1의 100배 · 심볼 tick에서 도출: `bin = 100 × tickSize`) |
| VP 계산(결정론) | 마감된 1m 봉의 **quote volume 전부를 그 봉 종가가 속한 bin**에 넣는다(봉 내 분배 없음) · 창 = 결정 봉 종가 **직전까지 마감된 1440봉**. **POC** = 최대 거래량 bin(동률이면 **더 낮은 가격**) · **VA 확장** = POC에서 위·아래 인접 bin 중 **거래량이 큰 쪽**을 하나씩 추가(동률이면 **아래쪽**), 누적 거래량이 전체의 **70% 이상**이 될 때까지 · **VAH = 포함된 최상단 bin의 상단 경계**, **VAL = 최하단 bin의 하단 경계**(bin 부분 포함 없음) |
| 레벨 집합 | 유효 스윙 레벨 전부 ∪ {POC, VAH, VAL}. **롱 후보 = mark 이하의 레벨(지지)**, **숏 후보 = mark 이상의 레벨(저항)** · 각 방향에서 **mark에 가까운 순 3개**만 사용 |
| 결합 레벨(binding) | 터치된 레벨이 그 트레이드의 결합 레벨이다. 한 봉에서 여러 레벨이 터치되면 **봉 극값(롱=low, 숏=high)에 가장 가까운 레벨**, 동률이면 **더 낮은 가격** |
| SL 앵커 | 결합 레벨이 VP(POC·VAH·VAL)여도 SL은 **확정된 유효 15m 스윙**에 건다: 롱이면 결합 레벨 **이하에서 가장 가까운 스윙 저점**, 숏이면 그 대칭. 그런 스윙이 없으면 **진입 건너뜀**(`no_sl_anchor`) |
| TP 레벨 선택 | 이익 방향(롱=위, 숏=아래)에서 **그 시각에 유효한** 레벨 중 가장 가까운 것 `Lv`. 없으면 `TP = 2R` |
| 동시 신호 | 같은 봉에서 롱·숏 확인이 동시에 서면 **둘 다 건너뜀**(`conflict_signal`) |
| ATR 정의 | Wilder ATR · **ATR_1m 기간 60** · ATR_15m 기간 14 |
| 밴드 | 레벨 ± `m × ATR_1m`, **m = 0.5**(점 레벨 금지 — tick 노이즈) |
| 터치 | 1m 봉의 low(롱) 또는 high(숏)가 밴드 안에 들어옴 |
| 거부 확인(confirmation) | 터치 봉 포함 **5봉 이내**에 1m **종가**가 밴드 밖(진입 방향 쪽)으로 마감 **그리고** 그 종가가 해당 봉 range의 상위 60%(롱)·하위 60%(숏)에 위치. **range < 1 tick(도지)이면 확인 없음**(0으로 나누지 않는다) |
| 진입 시점 | 거부 확인 봉의 **다음 1m 봉 첫 mark 틱**(엔진 `EntryIntent` → 실행 시점 재사이징 · 레지스트리 #7/#9 예상 체결가) |
| 방향 필터(Arm A만) | `TSMOM_4h = sign(close_4h[t] − close_4h[t−L])`, **L = 180봉 = 30일** — VCB T1_v2와 **같은 파라미터**(T1_v1 설계서 표 행 2: 30일=180봉 · Liu·Tsyvinski 2021 RFS 34(6) 암호 모멘텀 1~4주 · MOP 2012 JFE 104(2) 부호 전용) · 필터와 같은 부호의 셋업만 진입 · **4h 봉 마감 시각에만** 갱신 |
| 쿨다운 | 같은 레벨에서 청산 후 **60분** 재진입 금지 · 동시 포지션 **1개**(원웨이) |
| SL (**사용자 결정 2026-09-19 · (a)+(b)**) | **15m 스윙 레벨 바깥 + `1.0 × ATR_15m(14)`** — 롱: `SL = swing_low − 1.0×ATR_15m`. 진입 밴드(0.5×ATR_1m)는 **타이밍 전용**이고 SL 계산에 쓰지 않는다 |
| SL 바닥·천장 | `sl_dist ∈ [0.30%, 1.00%]` **하드** — 밖이면 **진입 건너뜀**(`decisions`에 `sl_dist_out_of_range` 사유 기록) |
| **건너뜀 비율 보고**(사용자 2026-09-19 · 분모 정의 Codex #9) | `skip_rate = sl_dist_out_of_range / 후보 셋업 수`를 **암별·창별(IS·OOS·전진)로 보고**. **분모 = S/R 터치 + 거부 확인 + (Arm A면) 방향 필터 + 쿨다운 + 단일 포지션 규칙까지 통과한 셋업 수**(즉 `sl_dist` 검사와 사이징·청산 게이트 **직전**). `no_sl_anchor`·`conflict_signal` 건너뜀도 같은 분모로 따로 보고 · **게이트 아님 · 무효화 임계 없음**(Codex 동의) |
| TP | 반대편 레벨 `Lv`까지 거리가 **1.5R 미만이면 TP = 2R**, 그 밖이면 **TP = Lv** |
| 트레일링 | +1R 도달 후 `trail_dist = 1.0 × ATR_15m(14)`(SL과 **같은 15m 스케일** · mark 되돌림 시 MARKET reduceOnly 전량) |
| SL/TP 판정 가격 | **mark**(레지스트리 #5 `SL_TRIGGER_BASIS`) · 백테스트도 같은 계열: 아카이브 `mark_*` 1m 시계열로 SL/TP·트레일링을 판정하고, 진입 체결가는 그 mark에 레지스트리 #7 모델(±2 bps 불리 + 불리 tick)을 적용 · kline last는 레벨·ATR·VP 계산에만 사용 |
| 사이징 | 기존 코드 그대로: `risk_pct = 1%` · `l_min/l_max = 50/100` · SL 거리 → 레버리지 도출(레지스트리 #2·#4) · 게이트 `sl_dist × 1.5 < liq_dist` **및** `liq_dist − sl_dist ≥ 10 bps`(#5) · `pos_pct` 캡 0.40 |
| 스케일 정합 | **SL·트레일링 = 15m(ATR_15m)** · **진입 타이밍 = 1m**(밴드·mark 틱 감시) · **방향 = 4h**. learnings의 실패 모양은 *SL이 감시 스케일보다 굵은* 경우(15m 버퍼 + 4h SL)였다 — 여기서는 **감시(1m mark 틱)가 SL 스케일(15m)보다 촘촘**해 방향이 반대다. ATR_1m은 진입 밴드에만 남고 SL 거리에 들어가지 않는다 |

`params_version = sr_v1` = 위 표 전체의 SHA256(구현 시 `strategies/trial01/config.py` 상단에 기록 · 값이 하나라도 바뀌면 새 버전·새 트라이얼). **별도 필드**로 기록하며 플라시보 시드(20260921)와 무관하다.

### 1-1. SL 거리·레버리지·비용의 산술 (**정정** · 2026-09-19)
🔴 **초안의 전제가 틀렸다.** 초안은 폐기된 식 `L = risk_pct / sl_dist`로 "50~100x와 시간 단위 보유는 양립 불가"라고 적었다.
현행 **B2 사이징**(`sizing/position.py`가 B2를 구현함을 코드로 확인)은 레버리지를 SL에서 유도하지 않는다:

```
budget   = equity × risk_pct
notional = budget / sl_dist                 # 위험 예산이 1차 제약
L        = [l_max … l_min] 중 청산 게이트를 통과하는 가장 높은 정수
margin   = notional / L                     # pos_pct는 도출값
게이트     = sl_dist × 1.5 < liq_dist  AND  liq_dist − sl_dist ≥ 10 bps   (레지스트리 #5)
```

정본 `size_entry` + 캡처 스냅샷 규칙으로 실측(equity 1,000 · risk_pct 1% · entry 75,700 · LONG · l∈[50,100]):

| sl_dist | ok | L | notional | margin | pos_pct | liq_dist | SL 손실 |
|---|---|---|---|---|---|---|---|
| 0.30% | ✅ | **100** | 3,330.80 | 33.31 | 3.33% | 0.5522% | 9.99 |
| 0.50% | ✅ | 83 | 1,968.20 | 23.71 | 2.37% | 0.7579% | 9.84 |
| 1.00% | ✅ | **51** | 984.10 | 19.30 | 1.93% | 1.5169% | 9.84 |
| 1.20% | ❌ | — | — | — | — | 1.5562% | `liq_distance` 거부 |

→ **50~100x 밴드와 시간 단위 보유는 공존한다**(사용자 정정 2026-09-19). 레지스트리 정정 행은 필요 없다.
천장 **1.00%**는 위 표의 실행 가능 경계(1.20%는 거부)이고, 바닥 **0.30%**는 비용에서 온다: `2R = 0.60%` vs 왕복 **0.14%** → 비용은 목표의 **23%**
(SL 1.00%면 2R = 2.00%, 비용 비중 **7%**). pos_pct 3.3%는 권고 하한(10%) 아래지만 **기록만** 한다(레지스트리 #2: 하한은 권고, 상한 0.40만 하드).

**남은 진짜 결함은 SL을 1m 스케일에 걸었던 것**이다(learnings "ATR 스케일 ≠ 실행 스케일 → 체계적 청산") → SL·트레일링을 **15m 스케일**로 올린다(위 표).

## 3. 게이트 (순서 고정)
> **적용 대상**(Codex 2026-09-19 #4): G1·G2·G3·G-B·벤치마크는 **Arm A**에만 적용한다 — 가설은 "A가 B보다 낫다"이지 "B도 수익이다"가 아니다.
> **Arm B**는 대조군이다: `n_eff ≥ 30`은 **A/B 짝지음 비교의 전제**로만 요구하고, B의 단독 지표(순엣지·Sharpe·n)는 **보고**한다.
| 게이트 | 기준(사전확약) |
|---|---|
| **G0 이벤트 수** | `n_eff = n / (1 + 4ρ̂) ≥ 30`(프로토콜 표기와 동일). **계획 ρ̄ = 0.15 → n ≥ 48**이고, **실측 ρ̂ > 0.15면 ρ̂로 다시 계산**해 미달이면 **검정력 부족**으로 실패 처리(임계 완화 금지). ρ̄ 근거: 보유 수 시간·하루 1~3회라 같은 4h 필터 구간을 공유하는 인접 트레이드의 수익률 자기상관을 0.15로 보수 가정(실측 ρ̂가 0.15를 넘으면 그 창은 **검정력 부족**으로 판정, 임계 완화 금지). **기대 표본 수치는 사전확약하지 않는다** — SL 하드 밴드(0.30~1.00%) 건너뜀 때문에 IS 전에는 알 수 없다. G0는 **실현 n**으로만 평가한다(48 미만이면 그 창은 검정력 부족) |
| **G1 총 엣지** | 비용 전 트레이드당 평균 순수익 > 0 이고 block bootstrap **97.5% CI**(Bonferroni α=0.025와 같은 수준) 하한 > 0 · 블록 = 24시간 · 10,000 재표본 |
| **G2 순 엣지** | **비용(§2) 차감 후** 트레이드당 평균 > 0 이고 같은 **97.5% CI** 하한 > 0. **경제적 임계 θ = +10 bps/트레이드** |
| **G3 OOS** | OOS 창에서 G2를 같은 부호로 통과(순엣지 > 0 · CI 하한 > 0) |
| **G-B 다중검정** | **PSR > 0.5** 이고 **n ≥ 30** 이고 **DSR > 0**(시도 수 **N = 2** = Arm A·B) · 유의수준 Bonferroni `α = 0.05/2 = 0.025` |
| **벤치마크** | ① **flat(무거래 · 수익 0) = 게이트**(Arm A 순수익 > 0) · ② **노출 정합 벤치마크 = 게이트**: 플라시보 **P1(무작위 타이밍 · 트레이드 수·보유시간 분포 일치)**가 바로 노출이 맞춰진 대조군이고 p95 우위가 필수다 — 즉 "같은 시간만큼 시장에 있었던 무작위 전략"을 이겨야 한다 · ③ **BTC 매수보유 = 보고만**(같은 창의 일별 Sharpe·순수익). 사용자 확정 2026-09-19(결정 A + 강화) |
| **A/B 비교** | Arm A 순엣지 > Arm B 순엣지 · **짝지음 차이의 block bootstrap 97.5% CI 하한 > 0**(G-B와 같은 Bonferroni 수준 · Codex #5) · 전제: Arm B `n_eff ≥ 30` |
| **G-F 전진(페이퍼 30일 · Arm A만)** | **통계 판정이 아니다**: 트레이드 > 0 · 사전등록 규칙과 실행의 일치(진입 사유·SL 거리·레버리지가 규칙과 같음) · 데이터 결손 0 · 순엣지 **부호**만 본다. 30일 기대 트레이드는 Arm A 약 15~45건으로 **G0(48)에 미달하므로 CI·PSR 판정을 하지 않는다** |
| **즉시 FAIL** | 성과 창에서 **트레이드 0건** = FAIL(생존 조건의 N/A와 구분) |

## 7. 판정 규칙 (3분류)
- **ACCEPT**: G0~G3 · G-B · 벤치마크(flat 게이트 + P1 노출 정합 게이트) · A/B 비교 · 플라시보 4층을 **전부** 통과.
  - 판정 주체는 **Arm A**다. **A/B 비교를 통과해도 Arm A가 단독으로 G2를 못 넘으면 REJECT**(필터가 상대적으로 낫다는 것만으로는 알파가 아니다).
  - 이때 **Arm A 일별 Sharpe < BTC 매수보유 Sharpe**이면 판정 문자열은 **`ACCEPT — 수동(매수보유)을 이기지는 못함`**(§8-1 · 라이브 전환 판단용 라벨이지 판정 변경이 아니다).
- **REJECT**: 하나라도 실패. 실패 보고에는 **반드시** 아래 구분을 적는다.
  - **검정력 부족**: 사후 MDE(검정력 80% · α = 0.025 · 관측된 트레이드당 순수익 표준편차와 n으로 계산) **> 2θ(= 20 bps)** → "표본이 답을 못 준다".
  - **효과 부재**: 사후 **MDE < 0.5θ(= 5 bps)** 이고 관측 순엣지 CI가 θ를 배제 → **잘 검정된 음성 결과**(연구 성과로 기록).
  - 그 사이(5~20 bps): **결론 보류형 REJECT** — 창을 늘리려면 **새 트라이얼**로 등록.
- **폐기**: 측정 전 설계 결함·데이터 부재 등으로 트라이얼 자체를 접는 경우(성과 판정 아님). **측정 중 하네스 결함도 폐기다** — 예: P1 추출 실패율 > 1%(P1 행 (f)). 폐기는 가설을 검정하지 않았다는 기록이며, 고친 하네스로 다시 하려면 새 트라이얼(N+1)이다.
- 판정 뒤 **진단 티어시트(quantstats 등)는 판정에 포함하지 않고 중간보고에도 붙이지 않는다**(research-protocol §4).

## 8. 결과를 본 뒤 금지되는 것
임계(θ·CI·PSR/DSR·ρ̄)·창 길이·밴드 m·ATR 기간·스윙 k·VP bin/창·필터 k·쿨다운·TP/트레일링 규칙·비용값·게이트 순서·플라시보 구성 — **어느 하나도 바꾸지 않는다**. 바꾸려면 **새 트라이얼 행 + 새 사전등록**이고 N 카운터가 오른다(Bonferroni 임계 상승). 파라미터 재탐색·창 이동·"한 번만 더" 재실행 금지. holdout(OOS) 개봉 횟수를 보고서에 기록한다 — **정상값 = 1회(G3)**, 그 이상이면 프로토콜 위반으로 공개한다.

## 8-1. 벤치마크 — **확정**(사용자 2026-09-19 · Codex #3에 대한 답)
- **결정 = A + 강화**: BTC 매수보유 Sharpe는 **보고**하고 게이트로 두지 않는다.
- **근거**: 매수보유 대비 성적은 *그 창이 강세장이었는가*를 재는 것이지 *알파가 있는가*를 재지 않는다.
  롱/숏 양방향이면서 하루 일부만 시장에 있는 전략은 **진짜 알파가 있어도 추세 창에서 매수보유에 뒤질 수 있다**.
- **Codex #3에 대한 실질 답변**: 노출이 맞춰진 벤치마크 게이트는 **이미 있다** — 플라시보 **P1(무작위 타이밍 · 트레이드 수와 보유시간 분포를 실제와 일치)**가
  본질적으로 "같은 노출의 수동 대조군"이고, 그 분포의 **p95 초과가 필수 조건**이다. 즉 "최종 벤치마크 없이 ACCEPT"는 불가능하다.
- **판정 라벨 사전확약**: ACCEPT이면서 **Arm A 일별 순자산 Sharpe < 매수보유 Sharpe**이면 판정을 그대로
  **`ACCEPT — 수동(매수보유)을 이기지는 못함`**으로 기록한다. 이 라벨은 **라이브 전환 판단(사용자 재량)**에 쓰이고 **과학적 판정(ACCEPT/REJECT)을 바꾸지 않는다**.

  장래 브라켓·수수료 레짐에서 천장이 결박되면 그것은 `sl_dist_out_of_range` 건너뜀으로 **관측**된다 — 튜닝이 아니다. **사전확약 유지**.
- **`sl_dist` 건너뜀**: 결정 시점 정보만 쓰므로 **룩어헤드 없이 n만 줄인다**. 다만 **변동성 조건부 선택**이므로 위 표의 `skip_rate`를 창별로 보고한다.
  **무효화 임계는 두지 않는다** — Codex가 근거를 들어 주장하면 그때 새 행으로 결정한다.

## 10. N 카운터
- 이 저장소 첫 트라이얼. **N = 2**(Arm A · Arm B)로 계산한다 — 두 암을 같은 데이터에서 함께 평가하므로 Bonferroni `α = 0.025`, DSR의 시도 수 2.
- 이후 파라미터 변형·창 변경을 시도하면 N이 오르고 임계가 올라간다(§8).
