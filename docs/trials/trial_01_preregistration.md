## 0. 가설 (한 문장)
**4h 시계열 모멘텀 부호 방향으로만, 1m 결정론적 S/R 밴드까지 되돌린 뒤 거부(rejection)가 확인될 때 진입하면, 같은 진입·SL·TP를 필터 없이 쓰는 대조군보다 비용 차감 후 트레이드당 순엣지가 높다.**
- **Arm A(주)**: 방향 필터 = 4h TSMOM 부호(VCB T1_v2와 같은 가족) + S/R 되돌림 진입.
- **Arm B(대조)**: 진입·SL·TP 규칙 동일, **방향 필터 없음**(양방향 모두 진입).
- A/B가 의미 있는 이유: 필터가 셋업의 약 절반(부호가 반대인 쪽)을 제거하므로 **진입 조건이 실질적으로 갈린다**(learnings의 "A/B는 진입조건이 갈려야 의미" 조건 충족). 두 암은 같은 후보 셋업 집합에서 서로 다른 부분집합을 취한다 — 중복 트레이드가 아니다.
- 보유 기대: 수 시간 · 하루 1~3회. **1m은 타이밍 스케일이지 신호 스케일이 아니다**(§1 비용 산식 참조).

| 진입 시점 | 거부 확인 봉의 **다음 1m 봉 첫 mark 틱**(엔진 `EntryIntent` → 실행 시점 재사이징 · 레지스트리 #7/#9 예상 체결가) |
| 방향 필터(Arm A만) | `TSMOM_4h = sign(close_4h[t] − close_4h[t−L])`, **L = 180봉 = 30일** — VCB T1_v2와 **같은 파라미터**(T1_v1 설계서 표 행 2: 30일=180봉 · Liu·Tsyvinski 2021 RFS 34(6) 암호 모멘텀 1~4주 · MOP 2012 JFE 104(2) 부호 전용) · 필터와 같은 부호의 셋업만 진입 · **4h 봉 마감 시각에만** 갱신 |
| 쿨다운 | 같은 레벨에서 청산 후 **60분** 재진입 금지 · 동시 포지션 **1개**(원웨이) |
| SL | 밴드 바깥 끝 + 버퍼 `0.25 × ATR_1m` (롱: `level − m·ATR_1m − 0.25·ATR_1m`) |
| TP | 진입 방향의 가장 가까운 유효 반대편 레벨 `Lv`까지 거리가 **1.5R 미만이면 TP = 2R**, 그 밖이면 **TP = Lv**(두 구현자가 갈리지 않게 규칙 하나로 고정) |
| 트레일링 | +1R 도달 후 `trail_dist = 1.0 × ATR_1m`(mark 기준 되돌림 시 MARKET reduceOnly 전량) |
| SL/TP 판정 가격 | **mark**(레지스트리 #5 `SL_TRIGGER_BASIS`) · 백테스트도 같은 계열: 아카이브 `mark_*` 1m 시계열로 SL/TP·트레일링을 판정하고, 진입 체결가는 그 mark에 레지스트리 #7 모델(±2 bps 불리 + 불리 tick)을 적용 · kline last는 레벨·ATR·VP 계산에만 사용 |
| 사이징 | 기존 코드 그대로: `risk_pct = 1%` · `l_min/l_max = 50/100` · SL 거리 → 레버리지 도출(레지스트리 #2·#4) · 게이트 `sl_dist × 1.5 < liq_dist` **및** `liq_dist − sl_dist ≥ 10 bps`(#5) · `pos_pct` 캡 0.40 |
| 스케일 정합 | SL·밴드·트레일링 전부 **ATR_1m**(실행 스케일 = 1m) — learnings "ATR 스케일 ≠ 실행 스케일 → 체계적 청산" 회피. 15m·4h는 **레벨 생성·방향 필터에만** 쓰고 SL 스케일로 쓰지 않는다 |

`params_version = sr_v1` = 위 표 전체의 SHA256(구현 시 `strategies/trial01/config.py` 상단에 기록 · 값이 하나라도 바뀌면 새 버전·새 트라이얼).

### 1-1. SL 거리와 비용의 산술 (앵커 전에 반드시 닫아야 하는 구멍 · **P1 결정 대기**)
스킬 `strategy-modules.md §1`의 사전 값: **1m ATR% ≈ 0.05~0.10%**. 위 표대로면
`R = (진입가 − 밴드 바깥) + 0.25×ATR_1m ≈ 0.75~1.0 × ATR_1m ≈ **0.04~0.10%**`, `2R ≈ 0.08~0.20%`.
**왕복 비용 14 bps = 0.14%** → 비용이 목표의 70~175%다. 그러면 이 설계는 *구조적으로* §7의 "30분 이하 신호는 비용이 엣지를 먹는다"에 들어가고,
"보유 수 시간·목표 ≳0.4~0.5%"라는 가설 문장과 모순된다. 숫자를 바꾸지 않고 앵커하면 트라이얼은 시작부터 실패가 예정돼 있다.
🔴 **P1 — 사용자가 하나를 고른다(앵커 전 확정 · 고른 값이 이 표를 대체한다)**:
- **(a) SL을 15m 스윙 레벨 바깥에 건다**: `SL = swing_level ∓ (b × ATR_1m)`, b를 사용자가 정한다(예 b = 6~10 → R ≈ 0.3~1.0%). 실행·모니터링은 1m mark 그대로.
- **(b) 최소 SL 거리 바닥**: `sl_dist = max(밴드+버퍼, floor)`, **floor = 0.30%** 고정(2R = 0.60% ≥ 4.3× 왕복비용). SL이 멀어지면 레버리지는 사이징 식이 자동으로 낮춘다(L = risk_pct/sl_dist → 1%/0.30% ≈ 33x < 50x 하한 → **진입 거부**가 되므로 risk_pct도 같이 정해야 한다: 예 risk_pct 0.5%면 L ≈ 17x로 더 낮아진다 · 50~100x 클램프와 충돌).
- **(c) 분(minute) 단위 보유를 인정하고 가설 문장을 고친다** — 이 경우 §9의 "30분 이하 신호와 다르다" 논거를 다시 써야 하고, 사실상 §7과 겹친다(권하지 않는다).
⚠️ (b)는 레버리지 클램프 50~100x와 정면충돌한다: **SL 0.30% · risk_pct 1%면 L_raw ≈ 3.3x**다. 50x 하한을 유지하면 SL은 **0.02% 수준**이어야 하고 그건 (c)다.
→ 즉 **"50~100x 클램프"와 "시간 단위 보유"는 동시에 성립하지 않는다.** P1은 사실상 *어느 쪽을 포기할지*의 결정이다(레버리지 범위를 이 트라이얼에 한해 낮추려면 레지스트리 정정 행이 필요하다).

- **왕복 14 bps** = taker 5 bps × 2(진입·청산) + 슬리피지 2 bps × 2(레지스트리 #7 · mark 대비 불리 방향 + 불리 tick).
- **펀딩**: 보유 중 지나는 8h 경계마다 **실제 펀딩율**(수집/아카이브 값)로 `signed_qty × mark × rate` 정산. 추정·평균값 금지.
- **꼬리표**: *"2026-09 페이퍼 레짐 · taker VIP0 · BTCUSDT · 페이퍼 14일차(레지스트리 #7/#9)에 재평가"*.
- 재평가로 값이 바뀌어도 **이 트라이얼의 판정은 소급 재개봉하지 않는다**(민감도만 기록 · research-protocol §2).
- 트레이드가 비용을 넘으려면 기대 이동 ≳ **0.4~0.5%** — 그래서 보유가 시간 단위여야 하고, 30분 이하 신호(§7 기각 목록)와 구조적으로 다르다.

## 3. 게이트 (순서 고정 · 암별로 각각 평가)
| 게이트 | 기준(사전확약) |
|---|---|
| **G0 이벤트 수** | `n_eff ≥ 30(1 + 4ρ̄)`, **ρ̄ = 0.15 가정** → **암당 n ≥ 48 트레이드**. ρ̄ 근거: 보유 수 시간·하루 1~3회라 같은 4h 필터 구간을 공유하는 인접 트레이드의 수익률 자기상관을 0.15로 보수 가정(실측 ρ̂가 0.15를 넘으면 그 창은 **검정력 부족**으로 판정, 임계 완화 금지). 기대 표본: IS 2.5년 ≈ 900~2,700 · OOS ≈ 80~240 |
| **G1 총 엣지** | 비용 전 트레이드당 평균 순수익 > 0 이고 block bootstrap **97.5% CI**(Bonferroni α=0.025와 같은 수준) 하한 > 0 · 블록 = 24시간 · 10,000 재표본 |
| **G2 순 엣지** | **비용(§2) 차감 후** 트레이드당 평균 > 0 이고 같은 **97.5% CI** 하한 > 0. **경제적 임계 θ = +10 bps/트레이드** |
| **G3 OOS** | OOS 창에서 G2를 같은 부호로 통과(순엣지 > 0 · CI 하한 > 0) |
| **G-B 다중검정** | **PSR > 0.5** 이고 **n ≥ 30** 이고 **DSR > 0**(시도 수 **N = 2** = Arm A·B) · 유의수준 Bonferroni `α = 0.05/2 = 0.025` |
| **벤치마크** | ① **flat(무거래 · 수익 0)**은 **게이트**: Arm A 순수익 > 0(G2와 동치) · ② **BTC 매수보유**는 같은 창의 Sharpe·순수익을 **보고**한다. 🔴 **P3 결정 대기**: 매수보유 Sharpe 우위를 ACCEPT 조건(게이트)으로 둘지 — 하루 몇 시간만 포지션을 드는 전략에는 구조적으로 불리할 수 있다(초안 권고: 게이트는 flat, 매수보유는 보고) |
| **A/B 비교** | Arm A 순엣지 > Arm B 순엣지(차이의 block bootstrap 95% CI 하한 > 0) — 필터가 값을 더해야 한다 |
| **G-F 전진(페이퍼 30일)** | **통계 판정이 아니다**: 트레이드 > 0 · 사전등록 규칙과 실행의 일치(진입 사유·SL 거리·레버리지가 규칙과 같음) · 데이터 결손 0 · 순엣지 **부호**만 본다. 30일 기대 트레이드는 Arm A 약 15~45건으로 **G0(48)에 미달하므로 CI·PSR 판정을 하지 않는다** |
| **즉시 FAIL** | 성과 창에서 **트레이드 0건** = FAIL(생존 조건의 N/A와 구분) |

## 4-1. 단계(스테이징) — 순서를 어기면 프로토콜 위반
1. **앵커**(Drive createdTime) → 2. 구현(정본 코드) → 3. **IS 측정**(G0·G1·G2 + 플라시보 4층) → 실패면 여기서 **REJECT**(OOS 미개봉) →

## 4-2. Arm B를 실제로 어떻게 돌리는가 (🔴 **P2 결정 대기**)
엔진은 원웨이 **단일 포지션**이라 한 프로세스가 두 암을 동시에 들 수 없다. 전진 페이퍼에서 Arm B를 어떻게 둘지 앵커 전에 정한다.
- **(i) 별도 프로세스**: 두 번째 `var-dir`·DB·인스턴스 락 · `--no-telegram`(같은 봇 토큰으로 두 번 `getUpdates` 하면 409) · 메모리 +약 230 MB(1834 MB·swap 0 · 00:10 스파이크와 겹침 — D2 계측 기준으로는 빠듯하다).
- **(ii) 백테스트에서만 A/B, 전진은 Arm A만**: 전진 30일은 어차피 G-F(부호·생존)라 A/B 통계 비교가 성립하지 않는다 → **초안 권고**.
- **(iii) 그림자 계정**: 한 프로세스에서 Arm B를 주문 없이 장부로만 시뮬 — 코드가 늘고(두 번째 엔진 인스턴스) 안전 경로가 복잡해진다.

## 7. 판정 규칙 (3분류)
- **ACCEPT**: G0~G3 · G-B · 벤치마크 · A/B 비교 · 플라시보 4층을 **전부** 통과.
- **REJECT**: 하나라도 실패. 실패 보고에는 **반드시** 아래 구분을 적는다.
  - **검정력 부족**: 사후 MDE(검정력 80% · α = 0.025 · 관측된 트레이드당 순수익 표준편차와 n으로 계산) **> 2θ(= 20 bps)** → "표본이 답을 못 준다".
  - **효과 부재**: 사후 **MDE < 0.5θ(= 5 bps)** 이고 관측 순엣지 CI가 θ를 배제 → **잘 검정된 음성 결과**(연구 성과로 기록).
  - 그 사이(5~20 bps): **결론 보류형 REJECT** — 창을 늘리려면 **새 트라이얼**로 등록.
- **폐기**: 측정 전 설계 결함·데이터 부재 등으로 트라이얼 자체를 접는 경우(성과 판정 아님).
- 판정 뒤 **진단 티어시트(quantstats 등)는 판정에 포함하지 않고 중간보고에도 붙이지 않는다**(research-protocol §4).

## 8. 결과를 본 뒤 금지되는 것
임계(θ·CI·PSR/DSR·ρ̄)·창 길이·밴드 m·ATR 기간·스윙 k·VP bin/창·필터 k·쿨다운·TP/트레일링 규칙·비용값·게이트 순서·플라시보 구성 — **어느 하나도 바꾸지 않는다**. 바꾸려면 **새 트라이얼 행 + 새 사전등록**이고 N 카운터가 오른다(Bonferroni 임계 상승). 파라미터 재탐색·창 이동·"한 번만 더" 재실행 금지. holdout 개봉 횟수를 보고서에 기록한다(목표 0).

## 9. §7 "이미 기각된 것"과의 대조 (겹치지 않는 이유)
| 기각된 것 | 이 트라이얼이 다른 점 |
|---|---|
| **돈치안 돌파 + 로지스틱 메타라벨(E2E #74, 효과 부재 MDE 4.2 ≪ 13 bps)** | 신호 가족이 반대다 — **돌파 추종이 아니라 되돌림(mean-reversion) 진입**이고, 채널 돌파를 트리거로 쓰지 않는다(돈치안 계산 자체를 쓰지 않는다 · 저장소 규칙). 메타라벨(2차 분류기)도 없다: 진입은 규칙 하나로 결정된다. #74의 "효과 부재"는 *돌파 이벤트의 방향성*에 대한 결론이고, 여기서 검정하는 것은 *S/R 밴드에서의 거부 + 상위 스케일 모멘텀 부호*다. |
| **변동성/챕 레짐 base signal(E2E #109~111)** | 레짐 라벨을 **신호로 쓰지 않는다**. 변동성은 ATR을 통해 **밴드 폭·SL 거리·레버리지**에만 들어간다(사이징 경로). 방향 결정은 4h TSMOM 부호 하나이고, Arm B는 그마저 없다. |
| **스프레드 base signal(#112~113)** | 호가 스프레드·오더북 피처를 **입력에 쓰지 않는다**(1m kline + 거래량만). |
| **VPIN(방향 신호 아님)** | 주문흐름 독성 지표를 쓰지 않는다. 거래량은 **VP 레벨 위치 계산**에만 쓰고 방향 판단에 쓰지 않는다. |
| **펀딩 단독(비용 미달)** | 펀딩은 **신호가 아니라 비용**으로만 들어간다(§2). |
| **30분 이하 단기 신호(비용이 엣지를 먹음)** | 보유 기대 **수 시간**, TP = 2R 또는 스윙 극점, SL ≈ 0.2~0.5% → 목표 이동 ≳ 0.4~0.5% vs 왕복 14 bps. **1m은 진입 타이밍 해상도**일 뿐 신호 주기가 아니다. 하루 1~3회 빈도도 P1s(초단타)와 구조적으로 다르다. |
| **분위수 AND 결합으로 표본 파괴** | 조건은 2개(필터 부호 · 밴드 거부)뿐이고 분위수 조건이 없다. 기대 표본 IS 900~2,700으로 G0(48)을 크게 넘는다. |
| **"인프라 동작"을 성공으로 부르는 스코프 드리프트** | 성공 정의는 **비용 차감 후 순엣지와 플라시보 우위**뿐이다. 봇이 잘 도는 것은 판정에 들어가지 않는다. |

## 10. N 카운터
- 이 저장소 첫 트라이얼. **N = 2**(Arm A · Arm B)로 계산한다 — 두 암을 같은 데이터에서 함께 평가하므로 Bonferroni `α = 0.025`, DSR의 시도 수 2.
- 이후 파라미터 변형·창 변경을 시도하면 N이 오르고 임계가 올라간다(§8).
