## §0. 위상·우선순위 (이 블록이 본문보다 우선한다)

> **이 §0은 헌법의 최상위 조항이다. 아래 §1~§18 본문과 충돌하면 §0이 이긴다.**

### 0.1 이 문서의 위상
- 이 문서는 **"런타임 진리원"이 아니라 "검증된 참조 + 드리프트 감지 기준선"**이다.
- 봇의 실제 매매 파라미터(tickSize·stepSize·MMR·수수료·브라켓·펀딩 cap)는 **기동·주기적으로 인증 API에서 동적 조회**하거나 **캡처 스냅샷(`snapshots/*.json`)에서 로드**한다. **코드에 숫자 리터럴로 박으면 그 자체가 헌법 위반**이다(`기본환경설정_v2 §3·§12.2`).
- **값 신뢰도 범례**: `[DOC]` 공식문서 검증(구조·규칙·의미) / `[LIVE-ONLY]` 시점에 따라 변함, 반드시 런타임 조회 / `[DERIVED]` 위 값에서 계산되는 파생식.

### 0.2 주문 정책 — 진입·청산 전부 MARKET (BREAKING 우선)
- **이 봇은 진입·청산 모두 `type=MARKET`만 사용한다**(`기본환경설정_v2 §2`). `side`는 **BUY/SELL 대문자만**, 청산은 **`reduceOnly=true`**.
- 본문 §2·§7에 STOP/STOP_MARKET/TAKE_PROFIT/TAKE_PROFIT_MARKET/TRAILING_STOP_MARKET가 "거래소 지원 유형"으로 **나열**돼 있으나, **이 봇은 이들을 사용하지 않는다.** SL/TP는 **봇이 모니터링 후 MARKET reduceOnly로 청산**한다.
- ⚠️ **C1 (Algo 이관, 2025-12-09)**: 서버측 `STOP/TAKE_PROFIT/TRAILING`은 `/fapi/v1/order`에서 제거되어 **`POST /fapi/v1/algoOrder`로 이관**됐다. 구 엔드포인트는 `-4120`으로 거부된다. 따라서 본문에 남아 있을 수 있는 "서버측 STOP/TP를 `/fapi/v1/order`에 넣는" 서술은 **폐기**다. MARKET 전용이므로 애초에 해당 없음.
- ⚠️ **C2**: `stopPrice/closePosition/workingType/priceProtect/callbackRate`는 `/fapi/v1/order` 요청 표에서 제거됨.

### 0.3 순간값(비고정) — 기준선 표에 넣지 않는다 (B1)
> `markPrice/indexPrice/lastFundingRate/interestRate/nextFundingTime`는 매초·매 8시간 바뀐다. **드리프트 기준선이 아니라 시세다.** 봇은 항상 런타임 재조회로 쓴다. → §18 하네스 비교 대상에서 **제외**.
> 스냅샷 시점 관측치(2026-06-02 22:38:50 UTC, **참고용**): `markPrice 67080.20`, `indexPrice 67099.33`, `estimatedSettlePrice 67219.67`, `lastFundingRate 0.00009514`, `interestRate 0.00010000`, `nextFundingTime 1780444800000`(2026-06-03 00:00 UTC, **이미 경과**).

### 0.4 🚨 기동 게이트 — 마진 타입 강제 (B2, BREAKING)
> **실측 계정 = 원웨이 + 교차(CROSS)** 인데, 운영 의도(`기본환경설정_v2`)는 **격리(ISOLATED)** 다. 방치하면 §4 격리 청산공식·리스크 계산이 전부 어긋난다. 봇 `_setup()`은 **반드시**:
> 1. `GET /fapi/v2/positionRisk` → `marginType` 확인.
> 2. `ISOLATED`가 아니면 → 포지션·미체결 0 확인 후 `POST /fapi/v1/marginType {symbol:"BTCUSDT", marginType:"ISOLATED"}`.
> 3. 재조회로 `isolated=true` **확정**. **LIVE 모드에서 실패 시 기동 중단**(진입 금지, 청산만 허용).
> - **PAPER 모드는 계정 SET 금지(읽기만) — WARNING 로그만, 기동 계속**(`기본환경설정_v2 §4.1`).
> - ⚠️ 격리 전환 전 첫 하네스 실행은 마진에서 **BREAKING이 뜨는 게 정상**(설계대로). 전환·재조회 확정 후 해소.

### 0.5 ⚠️ maxNotionalValue 혼동 금지 (B3)
> `positionRisk.maxNotionalValue`(예 `480000000`)는 **현재 레버리지·계정 설정 기준 한도**이지 §3 브라켓의 `notionalCap`이 아니다. 포지션 사이징·마진 가드는 **§3 leverageBracket(런타임 조회)** 을 진리원으로 쓰고, 이 필드와 절대 섞지 마라.

### 0.6 펀딩 (8/N) 정규화
- 펀딩 인터벌이 8h가 아닌 구간(cap/floor 도달 시 1h 등)에서는 펀딩비율을 **`/(8/N)`** 으로 정규화해 일일 총비용을 동일화한다(2025-09-18 도입). `fundingInfo`의 `disclaimer=true/updateTime=null`(표준 cap)이면 cap/floor는 런타임 재확인.

## ⚠️ 마진콜 방지 — 주문 파라미터 완전 정리 (CRITICAL)

> **실전 경고**: `side` 파라미터에 `"LONG"` 또는 `"SHORT"`를 사용하면 **주문 거부 또는 반대 방향 체결**로 마진콜 발생 가능

### 파라미터 구분표

| API 파라미터 | 허용 값 | 절대 금지 |
|-------------|---------|----------|
| `side` | **`"BUY"`** 또는 **`"SELL"`** 만 허용 | `"LONG"`, `"SHORT"` 절대 불가 |
| `positionSide` | `"BOTH"` (One-way) / `"LONG"` / `"SHORT"` (Hedge) | 모드와 다른 값 사용 금지 |
| `reduceOnly` | `"true"` — **One-way 모드 전용** | Hedge 모드에서 사용 시 에러 발생 |

### One-way 모드 주문 매트릭스 (기본값, RL 봇 추천)

```
포지션 모드: dualSidePosition = false
positionSide = "BOTH" (생략 가능)

┌─────────────────┬──────────┬───────────────┬────────────────┐
│ 목적             │ side     │ positionSide  │ reduceOnly     │
├─────────────────┼──────────┼───────────────┼────────────────┤
│ LONG 진입 (오픈) │ "BUY"   │ "BOTH"        │ 사용 안 함     │
│ LONG 청산 (클로즈)│ "SELL" │ "BOTH"        │ "true" ← 필수  │
│ SHORT 진입 (오픈)│ "SELL"  │ "BOTH"        │ 사용 안 함     │
│ SHORT 청산 (클로즈)│ "BUY" │ "BOTH"        │ "true" ← 필수  │
└─────────────────┴──────────┴───────────────┴────────────────┘
```

> `reduceOnly="true"` — 기존 포지션 감소만 허용. 포지션 없으면 주문 거부.

### Hedge 모드 주문 매트릭스

```
포지션 모드: dualSidePosition = true
positionSide = "LONG" 또는 "SHORT" (명시 필수)
reduceOnly → Hedge 모드에서 완전 금지 (에러 발생)

┌─────────────────┬──────────┬───────────────┬──────────────────────────────┐
│ 목적             │ side     │ positionSide  │ 비고                         │
├─────────────────┼──────────┼───────────────┼──────────────────────────────┤
│ LONG 진입 (오픈) │ "BUY"   │ "LONG"        │                              │
│ LONG 청산 (클로즈)│ "SELL" │ "LONG"        │                              │
│ SHORT 진입 (오픈)│ "SELL"  │ "SHORT"       │                              │
│ SHORT 청산 (클로즈)│ "BUY" │ "SHORT"       │ ← 이전 문서 "(불가,주의)" 오류 수정! │
└─────────────────┴──────────┴───────────────┴──────────────────────────────┘
```

> ⚠️ **Hedge 모드에서 `BUY + positionSide="SHORT"`는 완전히 유효한 주문**입니다.
> SHORT 포지션을 청산(Close Short)할 때 사용하며, `"불가"` 표기는 잘못된 정보입니다.

### Python 빠른 참조

```python
# ============================================================
# One-way Mode (권장) — side는 항상 "BUY" 또는 "SELL"
# ============================================================

# LONG 진입
client.new_order(symbol="BTCUSDT", side="BUY",  type="MARKET", quantity=qty)

# LONG 청산
client.new_order(symbol="BTCUSDT", side="SELL", type="MARKET", quantity=qty, reduceOnly="true")

# SHORT 진입
client.new_order(symbol="BTCUSDT", side="SELL", type="MARKET", quantity=qty)

# SHORT 청산
client.new_order(symbol="BTCUSDT", side="BUY",  type="MARKET", quantity=qty, reduceOnly="true")

# 전량 청산 (포지션 방향 자동 판단)
position_amt = float(client.get_position_risk(symbol="BTCUSDT")[0]['positionAmt'])
if position_amt != 0:
    close_side = "SELL" if position_amt > 0 else "BUY"  # LONG이면 SELL, SHORT이면 BUY
    client.new_order(
        symbol="BTCUSDT",
        side=close_side,
        type="MARKET",
        quantity=abs(position_amt),
        reduceOnly="true"
    )
```

#### MARKET_LOT_SIZE (시장가 수량 필터) — **심볼별 상이 (v6 보강)**
- 시장가(MARKET) 주문에 **별도** 적용 (LIMIT용 LOT_SIZE와 *다른* maxQty). 진입·청산 전부 MARKET인 봇엔 **이 maxQty가 1주문 상한**.
- 심볼별 `maxQty`(2026-06-19 실측): **ETH 2,000 · XRP 2,000,000 · BTC 120 · SOL 80,000 · BNB 2,000**. `minQty`/`stepSize`는 LOT_SIZE와 동일(ETH 0.001 / XRP 0.1 / BTC 0.001).
- 1주문이 maxQty 초과 시 거부(-1013) → 대형 주문은 분할 필요(봇 사이즈로는 비도달이나 명문화). 전체 심볼 값=§1.0(B).


- **최소 주문 금액 = 50 USDT** (수량 × 가격 ≥ 50)

### Python 수량/가격 정규화

```python
import math
from decimal import Decimal, ROUND_HALF_UP

def normalize_quantity(qty: float, step_size: float = 0.001) -> float:
    """주문 수량을 stepSize에 맞게 내림 (Binance LOT_SIZE: floor 필수)"""
    precision = int(round(-math.log(step_size, 10)))
    factor = 10 ** precision
    return math.floor(qty * factor) / factor

def normalize_price(price: float, tick_size: float = 0.10) -> float:
    """주문 가격을 tickSize에 맞게 반올림 (Decimal로 부동소수점 오차 방지).

    ⚠️ float 나눗셈(price / tick_size) 방식은 피할 것:
       99999.95 / 0.1 → 999999.4999... → 잘못된 내림 발생.
    Decimal str 변환 → ROUND_HALF_UP로 표준 반올림 보장.
    """
    tick = Decimal(str(tick_size))
    return float(Decimal(str(price)).quantize(tick, rounding=ROUND_HALF_UP))

# 예시
qty = normalize_quantity(0.0237)    # → 0.023
price = normalize_price(45123.456)  # → 45123.5
price = normalize_price(99999.95)   # → 100000.0  (float 나눗셈 방식이면 오계산)
```

#### 🆕 정규화 *순서* 규칙 (v6 — "전략 OK인데 주문 거부"의 전형 함정 차단)
필드값만으론 안 보이는 **절차 규칙**. 순서를 틀리면 좋은 신호도 거부된다:
1. **수량 = stepSize로 내림(floor)** — 올림 금지(-1111 precision / -1013 LOT_SIZE). `quantityPrecision` 자릿수.
2. **⚠️ 내림 *후* `qty × price ≥ MIN_NOTIONAL` 재확인** — 내림이 명목을 하한 *아래로* 밀 수 있다(예: XRP step 0.1, MIN_NOTIONAL 5, 가격 0.5 → qty 9.x를 9.0으로 내리면 명목 4.5 < 5 → **-4164 거부**). 미달이면 **한 step 올리거나(여유 자본 시) 주문 포기**(추격 금지). 신규진입만 해당(reduceOnly 청산은 면제).
3. 가격 = tickSize 배수(`pricePrecision`). LIMIT은 PERCENT_PRICE(±5%)·triggerProtect(±5%) 범위 내로 클리핑.
4. **모든 값은 심볼별**(step/tick/MIN_NOTIONAL 상이, §1.0) — 런타임 조회값 사용, 리터럴 금지.

```python
def size_ok(qty, price, step, min_notional):
    """내림 후 명목 재확인 — 신규진입 게이트. 반환 (정규화수량, 진입가능여부)."""
    q = math.floor(qty / step) * step
    return q, (q * price >= min_notional)   # False면 한 step 올리거나 주문 포기
```

> **에러코드 주의**: 본 문서의 코드(-4164/-1111/-1013/-1015 등)는 *대표값*이며 **거부 시 응답의 실제 `code`/`msg`를 로깅**해 대조하라(바이낸스가 코드 매핑을 변경할 수 있음). -4164=MIN_NOTIONAL 미달이 가장 흔함.

## 4. 증거금 & 청산 공식

### 4.1 핵심 용어

| 용어 | 정의 |
|------|------|
| **Entry Price** | 평균 진입가격 |
| **Mark Price** | 청산 기준가 (지수가격 + 펀딩 데이터 혼합) |
| **Last Price** | 최근 체결가 |
| **Notional Value** | 포지션 명목가치 = 수량 × Mark Price |
| **Initial Margin (IM)** | 초기 증거금 = Notional / Leverage |
| **Maintenance Margin (MM)** | 유지 증거금 = Notional × MMR - CumB |
| **Margin Balance** | 지갑잔액 + 미실현손익 |
| **Unrealized PnL** | 미실현 손익 |

### 4.2 미실현 손익 계산

```python
# One-way 모드 기준
def unrealized_pnl(position_amt: float, entry_price: float, mark_price: float) -> float:
    """
    position_amt > 0: LONG
    position_amt < 0: SHORT
    """
    return position_amt * (mark_price - entry_price)

# 예시
# LONG 0.1 BTC, 진입 50,000, 현재 마크 52,000
upnl = unrealized_pnl(0.1, 50000, 52000)  # → +200 USDT

# SHORT 0.1 BTC, 진입 50,000, 현재 마크 48,000
upnl = unrealized_pnl(-0.1, 50000, 48000)  # → +200 USDT
```

### 4.3 유지증거금 계산

```python
def maintenance_margin(notional: float, mmr: float, cum_b: float) -> float:
    """
    notional: 명목가치 (수량 × 마크가격)
    mmr: 유지증거금률 (예: 0.004 = 0.4%)
    cum_b: 브라켓 누적 유지증거금 보정값
    """
    return notional * mmr - cum_b
```

### 4.4 청산가격 계산 (Liquidation Price)

> 출처: Binance 공식 문서 §11 (Liquidation Price Formula)

#### 격리 마진 (Isolated) + One-way 모드

```
LONG 청산가 = Entry Price × (1 - 1/Leverage + MMR)
SHORT 청산가 = Entry Price × (1 + 1/Leverage - MMR)
```

#### 정확한 공식 (Isolated One-way)

```
청산가 (LONG):
  Liq_Price = Entry × (1 - IMR + MMR)
            = Entry × (1 - 1/Leverage + MMR)

청산가 (SHORT):
  Liq_Price = Entry × (1 + IMR - MMR)
            = Entry × (1 + 1/Leverage - MMR)
```

> ⚠️ **실제 청산 트리거**: `Mark Price`가 `liquidationPrice`에 도달할 때 강제청산 발동

#### Python 구현

```python
def calc_liquidation_price(
    side: str,           # "LONG" or "SHORT"
    entry_price: float,
    leverage: int,
    mmr: float = 0.004,  # Bracket 1 (0.4%), 격리 마진 5배 레버리지
) -> float:
    """
    격리 마진 One-way 모드 청산가 근사 계산.
    실제 청산가는 /fapi/v2/positionRisk 의 liquidationPrice 필드를 사용할 것.
    """
    imr = 1.0 / leverage
    if side == "LONG":
        return entry_price * (1 - imr + mmr)
    elif side == "SHORT":
        return entry_price * (1 + imr - mmr)
    raise ValueError("side must be 'LONG' or 'SHORT'")

# 예시: 5x 격리, LONG, 진입 50,000
liq = calc_liquidation_price("LONG", 50000, leverage=5, mmr=0.004)
# → 50000 × (1 - 0.2 + 0.004) = 50000 × 0.804 = 40,200 USDT

# 안전 거리
safety_margin = (50000 - liq) / 50000  # → 19.6%
```

#### 교차 마진 (Cross) 청산가 — 복잡한 공식

```
Cross 청산가 (LONG) =
  (WB - TMM1 + UPNL1 + cumB + Position_BOTH × EP_BOTH) /
  (Position_BOTH × (1 - MMR_B))

Cross 청산가 (SHORT) =
  (WB - TMM1 + UPNL1 + cumB - Position_BOTH × EP_BOTH) /
  (-Position_BOTH × (1 + MMR_B))
```

> WB=지갑잔액, TMM1=다른 포지션 유지증거금 합, UPNL1=다른 포지션 미실현손익 합

### 4.5 파산가격 (Bankruptcy Price)

```
LONG 파산가 = Entry × (1 - 1/Leverage)
SHORT 파산가 = Entry × (1 + 1/Leverage)

# 예시: 5x LONG, 진입 50,000
bankruptcy = 50000 × (1 - 0.2) = 40,000 USDT
```

- **청산가(Liquidation Price)**: 강제청산 시작 가격
- **파산가(Bankruptcy Price)**: 마진이 완전히 소진되는 가격
- 청산 시 잔여 마진은 보험기금(Insurance Fund)으로 이전

### 5.2 수수료 계산

```python
TAKER_FEE = 0.0005   # 0.05%
MAKER_FEE = 0.0002   # 0.02%

def calc_commission(qty: float, price: float, is_taker: bool = True) -> float:
    """거래 수수료 계산"""
    notional = qty * price
    fee_rate = TAKER_FEE if is_taker else MAKER_FEE
    return notional * fee_rate

# 예시: 0.1 BTC @ 50,000 USDT Taker
fee = calc_commission(0.1, 50000, is_taker=True)
# → 0.1 × 50,000 × 0.0005 = 2.5 USDT
```

### 5.3 수수료 유형 3가지

1. **Commission Fee** (거래 수수료): 주문 체결 시마다 발생
2. **Funding Fee** (펀딩비): 포지션 보유 시 주기적으로 발생
3. **Insurance Clearance Fee** (보험 청산 수수료): 강제청산 시 발생 (liquidationFee 필드)

### 5.4 강제청산 수수료

```
청산 수수료 = 포지션 명목가치 × liquidationFee
liquidationFee (2026-06-19 실측): ETH/XRP/BTC/BNB = 0.012500 (1.25%) · SOL = 0.015000 (1.5%, 상이)
```
> **심볼별 상이** — SOL만 1.5%. 청산가 공식(§4.4)의 유효 MMR에 가산되므로 심볼별 조회 필수(전체=§1.0 B). 미표기 유니버스 심볼은 런타임 exchangeInfo의 `liquidationFee` 사용.

### 6.3 펀딩비 계산 공식

```
Funding Rate = Premium Index + clamp(Interest Rate - Premium Index, 0.05%, -0.05%)

Premium Index = (Max(0, Impact Bid Price - Price Index) - Max(0, Price Index - Impact Ask Price)) / Price Index

Funding Amount = Notional Value × Funding Rate
              = Position Size × Mark Price × Funding Rate
```

```python
def calc_funding_fee(
    position_qty: float,
    mark_price: float,
    funding_rate: float,
    is_long: bool
) -> float:
    """
    펀딩비 계산.
    양수 funding_rate: LONG 납부 → SHORT 수령
    음수 funding_rate: SHORT 납부 → LONG 수령
    반환값이 음수면 지불, 양수면 수령
    """
    notional = abs(position_qty) * mark_price
    fee = notional * funding_rate
    # LONG은 positive rate 납부, SHORT은 수령
    return -fee if is_long else fee

# 예시: LONG 0.1 BTC, 마크가 50,000, 펀딩비 +0.01%
fee = calc_funding_fee(0.1, 50000, 0.0001, is_long=True)
# → LONG이 납부: -0.5 USDT (지갑에서 차감)
```

### 7.3 포지션 모드

#### One-way Mode (기본, RL 봇 추천)
```
positionSide = "BOTH"
BUY → LONG 포지션 증가 또는 SHORT 포지션 감소
SELL → SHORT 포지션 증가 또는 LONG 포지션 감소
reduceOnly = "true" → 기존 포지션 감소만 허용 (청산 주문)
```

#### Hedge Mode (헤지 모드)
```
포지션 모드: dualSidePosition = true
positionSide = "LONG" 또는 "SHORT" (명시 필수, "BOTH" 사용 불가)
reduceOnly → Hedge 모드에서 사용 금지 (에러 발생)

side="BUY"  + positionSide="LONG"  → LONG 포지션 진입  (Open Long)  ✅
side="SELL" + positionSide="LONG"  → LONG 포지션 청산  (Close Long) ✅
side="SELL" + positionSide="SHORT" → SHORT 포지션 진입 (Open Short) ✅
side="BUY"  + positionSide="SHORT" → SHORT 포지션 청산 (Close Short) ✅ ← 이전 문서 오류 수정
```

> ⚠️ **중요**: Hedge 모드에서 `side="BUY" + positionSide="SHORT"`는 SHORT 청산으로 완전히 유효!
> 이전에 "(불가, 주의)"로 표기된 것은 오류입니다. 이 잘못된 정보로 인해 SHORT 청산이 불가능하다고
> 착각하면 포지션이 청산되지 않아 마진콜로 이어질 수 있습니다.

> RL 봇 구현 시 **One-way Mode + reduceOnly** 조합 추천 (Hedge Mode보다 단순하고 안전)

## 8. Mark Price vs Last Price

### 차이점

| 구분 | Mark Price | Last Price |
|------|-----------|-----------|
| **용도** | 청산 트리거, 미실현손익 계산 | 실현손익 계산 |
| **계산** | Index Price + 편차 평균 | 마지막 체결가 |
| **의미** | 조작 방지용 기준가 | 실제 시장 체결가 |
| **API** | `/fapi/v1/premiumIndex` | `/fapi/v1/ticker/price` |

### Mark Price 계산

```
Mark Price = Index Price + EMA(Funding Basis, 8h 창)
Index Price = BTC 현물 주요 거래소 가격의 가중평균

Funding Basis = Max(Mark Price - Index Price, -FundingRateCap × Index Price)
```

### Python WebSocket 구현

> 🔴 **정정(2026-09-12) — 아래 예제는 지금 그대로 실행하면 한 건도 안 온다.** 🚫원문은 고치지 않고 남긴다.
> `wss://fstream.binance.com/ws/btcusdt@kline_15m`은 **두 가지가 동시에 깨져 있다**:
> ① **legacy 미라우팅 URL**(2026-04-23 폐기) ② **`@kline_*`은 `/market` 티어**.
> 즉 구독은 수락되고 **조용히 0건**이다. 현행 형태는
> **`wss://fstream.binance.com/market/ws/btcusdt@kline_15m`**(단일) 또는
> **`wss://fstream.binance.com/market/stream?streams=btcusdt@kline_15m`**(복합).
> 📌 위 §"WebSocket Base" 블록의 `/ws/`·`/stream?streams=` 표기도 **티어 접두어가 빠진 구판**이다.
> 상세·티어 지도·실측치는 §10 청산 행의 **재정정(2026-09-12)** 블록을 볼 것.

```python
import asyncio
import websockets
import json

async def btcusdt_kline_stream():
    uri = "wss://fstream.binance.com/ws/btcusdt@kline_15m"
    async with websockets.connect(uri) as ws:
        while True:
            msg = await ws.recv()
            data = json.loads(msg)
            k = data['k']
            # x=false: 형성 중 캔들 업데이트. 즉시 신호 판단/시장가 실행 가능.
            # x=true: 캔들 확정. 바 기반 회계/재학습/리포트 갱신에 사용.
            print(f"closed={k['x']} Open: {k['o']}, High: {k['h']}, "
                  f"Low: {k['l']}, Close: {k['c']}, "
                  f"Volume: {k['v']}")

asyncio.run(btcusdt_kline_stream())
```

> 🔴 **정정(2026-09-12)** — 위 표의 *"최신 1건"*은 **틀렸다. 공식 문구는 "가장 큰 1건"이다.**

> > *"Updated description: changed 'only the latest one liquidation order' to
> > 'only the largest one liquidation order' within 1000ms."*
>
> 적용 대상: `<symbol>@forceOrder`(Liquidation Order Streams) · `!forceOrder@arr`(All Market).
> 즉 v6가 인용한 문구는 **2026-04-10 이전 판**이며, v6 작성 시점(2026-06-03)에 이미 낡아 있었다.
>
> **출처**
> - https://developers.binance.com/docs/derivatives/usds-margined-futures/websocket-market-streams/Liquidation-Order-Streams
> - https://developers.binance.com/docs/derivatives/change-log
>
> ⚠️ **조회 한계 고지**: change log는 실제로 읽어 위 문장을 인용했다. 스트림 페이지 본문은
> **JS 렌더링 SPA라 자동 조회로 본문을 못 받았다**(홈 셸만 반환) — 문구 확정 근거는
> **change log 항목**이며, Tardis 문서가 인용한 구판 문구(*"only the latest liquidation per
> symbol in each 1000ms window"*)가 **정정 전 표현과 일치**하는 것으로 교차 확인했다.
>
> ---
>
> **(a) 🔴 이것은 스냅샷 스트림이다 — 청산 "총량"을 재면 안 된다.**
> 심볼당 **초당 최대 1건**만 밀어주고, 그 1건은 창 안에서 **가장 큰 주문**이다.
> → 이 스트림이 주는 것: **발생 사실 · 시각 · 방향(side) · 그 창의 최대 단일 주문**.
> → 이 스트림이 **주지 않는 것: 건수 합계 · 수량 합계 · 명목 합계.**
> 바쁜 창일수록 더 많이 버려지므로 **하향 편향이 청산이 몰릴 때 가장 커진다** —
> 즉 오차가 무작위가 아니라 **관심 있는 구간에 집중**된다. 청산 **강도/규모** 피처로 쓰면
> 그 편향을 그대로 학습한다. ⚠️v1.4 V4-2가 *"청산강도 추정"*을 사전등록 전 금지한 이유와 같은 지점.
>
> **(b) 소급 아카이브는 없다.**
> - `GET /fapi/v1/allForceOrders`: **우리 실측(2026-07·로컬·VPS 동일) "out of maintenance"** —
>   ⚠️단 change log에는 이 엔드포인트의 **폐기 항목이 없다**(있는 것은 2026-04-06의
>   `GET /fapi/v1/forceOrders` **"과거 90일만 조회 가능"** 주석 추가다). 즉 *"유지보수 중단"*은
>   **공식 고지가 아니라 우리 관측**이다 — 구분해 둔다.
> - `binance.vision`: liquidationSnapshot **데이터타입 자체 부재**(SP1 실측 2026-06-07).
> - → **전향 수집 또는 Tardis가 유일한 경로.** ⚠️Tardis도 같은 forceOrder 채널 파생이라
>   **같은 1초/최대1건 제약을 물려받는다**(Tardis 문서 자체가 구판 문구를 인용) — Tardis는
>   *"완전한 청산 원장"*이 아니다. 대조 대상으로 쓸 때 이 점을 전제해야 한다.
>
> ---
>
> 🔴 **재정정(2026-09-12 두 번째) — 엔드포인트 티어**
>
> 위 (b)에서 *"전향 수집 또는 Tardis뿐"*이라 적었는데, **전향 수집이 막혀 있다고 본 것 자체가 우리 측 오류**였다.
> Binance는 USDⓈ-M WS를 `/public`·`/market`·`/private` 티어로 쪼갰고 **legacy 미라우팅 URL은 2026-04-23 폐기**됐다.
> 그 뒤 legacy `/ws`·`/stream`은 `/market` 스트림 구독을 **정상 수락**(`{"result":null}`)하면서 **한 건도 보내지 않는다** — 에러도 로그도 없다.
>
> - 필요한 베이스: **`wss://fstream.binance.com/market/ws`** (또는 `/market/stream?streams=`)
> - 공지: https://developers.binance.com/docs/derivatives/usds-margined-futures/websocket-market-streams/Important-WebSocket-Change-Notice
> - 티어(실측 확정): **public** = `@trade`·`@bookTicker`·`@depth<levels>`·`@depth` · **market** = `@aggTrade`·`@markPrice`·`!markPrice@arr`·`@kline_*`·`@continuousKline_*`·`@miniTicker`·`@ticker`·**`@forceOrder`**·**`!forceOrder@arr`**·`@compositeIndex`·`!contractInfo`·`@assetIndex`
> - ⚠️`@trade`는 **공지 표에 없다** — 우리 실측으로 public 확정(legacy 90초: `@trade` 509건 vs `@aggTrade` **0건**).
>
> **실측(2026-09-12·VPS 도쿄)**
> | 엔드포인트 | 시간 | aggTrade | markPrice | forceOrder |
> |---|---|---|---|---|
> | `/market/ws` + JSON SUBSCRIBE | 240s | 1,590 | 81 | **40** |
> | `/market/stream?streams=` | 240s | 1,034 | 81 | **64**(`!forceOrder@arr`) |
> | legacy `/ws` | 90s | **0** | — | — |
> | legacy `/ws` (`@trade` 대조) | 90s | — | — | 509건 수신 |
>
> ✅ **즉 청산 전향 수집은 가능하다.** *"Binance가 WS로 안 준다"*는 종전 기재(2026-07 실측)는 **legacy URL 때문**이었다.
> 🔒 v1.2 §V2-2의 수집 전제는 **유효하다** — 07-26·09-12의 "반증"은 전부 legacy URL 측정이었다.
>
> **페이로드 추가 필드(실수신 원문에서 확인)**: 위 `o.*` 목록에 더해 **`o.ps`**(포지션 심볼) · **`o.st`**(1) 가 함께 온다.
> 실수신 예: `{"e":"forceOrder","E":1789220623104,"o":{"s":"ETHFIUSDT","S":"BUY","o":"LIMIT","f":"IOC","q":"371.6","p":"0.7635000","ap":"0.7557000","X":"FILLED","l":"127.1","z":"371.6","T":1789220622092,"ps":"ETHFIUSDT","st":1}}`

> forceOrder의 `side`: **SELL=롱 청산(강제매도), BUY=숏 청산(강제매수)**.
> 과거 L2 호가·청산은 Binance API 미제공 → Tardis.dev(Binance USDⓈ-M 2019-11-17~,
> 청산 2020-01-07~, OI 2020-05-13~; 월 1일 무료 다운로드).
> **binance.vision liquidationSnapshot은 데이터타입 자체 부재(SP1 실측 2026-06-07)** —
> 무료 다년 연속 청산 아카이브 없음.

### 12.2 핵심 게임 규칙 구현

```python
import numpy as np

class BinanceBTCUSdtEnv:
    """
    BTCUSDT USDⓈ-M Perpetual Futures RL 환경.
    Binance 공식 규칙을 정확히 구현한 게임 엔진.
    """

    def __init__(self, ohlcv: np.ndarray, funding_rates: np.ndarray,
                 initial_equity: float = 1000.0, leverage: int = 5):
        self.ohlcv          = ohlcv.astype(np.float32)
        self.funding_rates  = funding_rates.astype(np.float32)
        self.initial_equity = initial_equity
        self.leverage       = leverage
        self.mmr            = MMR        # 0.004 for Bracket 1
        self.T              = len(ohlcv)
        self._precompute()
        self.reset()

    def _precompute(self):
        """log-returns 사전 계산 (RevIN 정규화용)"""
        safe = np.clip(self.ohlcv, 1e-8, None).astype(np.float64)
        self._log_ret = np.diff(np.log(safe), axis=0).astype(np.float32)

    # ── 규칙 1: 수량 정규화 ──────────────────────────────────
    @staticmethod
    def floor_qty(qty: float) -> float:
        """stepSize=0.001 기준 내림 (Binance LOT_SIZE 규칙)"""
        return np.floor(qty * 1000) / 1000

    @staticmethod
    def round_price(price: float) -> float:
        """tickSize=0.1 기준 반올림 (Binance PRICE_FILTER 규칙).

        ⚠️ round(round(price / 0.1) * 0.1, 1) 방식은 float 나눗셈 오차로
           99999.95 → 99999.9 오계산 가능. Decimal 방식 사용.
        """
        from decimal import Decimal, ROUND_HALF_UP
        return float(Decimal(str(price)).quantize(Decimal("0.1"), rounding=ROUND_HALF_UP))

    # ── 규칙 2: 청산가 계산 (격리 마진, One-way) ────────────
    def liquidation_price(self, entry_price: float, side: str) -> float:
        """
        격리 마진 기준 청산가 근사값.
        실제 봇에서는 /fapi/v2/positionRisk 의 liquidationPrice 사용.
        """
        imr = 1.0 / self.leverage
        if side == "LONG":
            return entry_price * (1 - imr + self.mmr)
        elif side == "SHORT":
            return entry_price * (1 + imr - self.mmr)
        return 0.0

    # ── 규칙 3: 주문 실행 (수수료 포함) ─────────────────────
    def _execute_order(self, direction: str, target_pct: float,
                       price: float) -> float:
        """
        주문 실행 및 수수료 차감.
        Taker 수수료 = 명목가치 × 0.0005 (시장가 기준)
        """
        if direction == "FLAT":
            if self.position != 0.0:
                pnl  = self.position * (price - self.entry_price)
                cost = abs(self.position) * price * TAKER_FEE
                self.equity += pnl - cost
                self._trade_cost += cost
                self.position    = 0.0
                self.entry_price = 0.0
        else:
            side = 1.0 if direction == "LONG" else -1.0
            # 방향 전환 시 기존 포지션 먼저 청산
            if self.position != 0.0 and np.sign(self.position) != side:
                pnl  = self.position * (price - self.entry_price)
                cost = abs(self.position) * price * TAKER_FEE
                self.equity += pnl - cost
                self._trade_cost += cost
                self.position    = 0.0
                self.entry_price = 0.0
            # 신규 진입
            if target_pct > 0 and self.equity > 0:
                notional = self.equity * target_pct * self.leverage
                qty      = self.floor_qty(notional / (price + 1e-9))
                actual_notional = qty * price
                # 최소 명목가치 체크 (MIN_NOTIONAL = 50 USDT)
                if actual_notional < MIN_NOTIONAL:
                    return 0.0
                cost          = actual_notional * TAKER_FEE
                if self.equity < cost:
                    return 0.0
                self.equity   -= cost
                self._trade_cost += cost
                self.position  = side * qty
                self.entry_price = price * (1 + SLIPPAGE * side)
        return self._trade_cost

    # ── 규칙 4: 펀딩비 정산 ──────────────────────────────────
    def _apply_funding(self, step_idx: int, mark_price: float):
        """
        8시간(32 × 15분봉)마다 펀딩비 정산.
        cap/floor 도달 시 4스텝(1시간)으로 단축 가능.
        """
        self._funding_count += 1
        interval = FUNDING_INTERVAL_MIN // 15  # 32 스텝 (기본 8h)
        # TODO: cap/floor 도달 여부에 따라 interval = 4 (1h)로 동적 조정

        if self._funding_count >= interval and self.position != 0.0:
            fr = float(np.clip(self.funding_rates[step_idx],
                               FUNDING_FLOOR, FUNDING_CAP))
            # 펀딩비 = 명목가치 × 펀딩비율
            funding_pnl = -np.sign(self.position) * fr * abs(self.position) * mark_price
            self.equity += funding_pnl
            self._funding_count = 0

    # ── 규칙 5: 청산 체크 (Mark Price 기준) ──────────────────
    def _check_liquidation(self, mark_low: float, mark_high: float) -> bool:
        """
        바이낸스는 Mark Price 기준으로 청산을 트리거.
        LONG: 캔들 저가(Low)가 청산가 이하 → 청산
        SHORT: 캔들 고가(High)가 청산가 이상 → 청산
        """
        if self.position == 0.0:
            return False
        liq = self.liquidation_price(
            self.entry_price,
            "LONG" if self.position > 0 else "SHORT"
        )
        if self.position > 0 and mark_low <= liq:
            # LONG 강제청산: 청산가에서 정산
            loss = self.position * (liq - self.entry_price)
            liq_fee = abs(self.position) * liq * LIQUIDATION_FEE
            self.equity = max(0.0, self.equity + loss - liq_fee)
            self.position    = 0.0
            self.entry_price = 0.0
            return True
        elif self.position < 0 and mark_high >= liq:
            # SHORT 강제청산
            loss = self.position * (liq - self.entry_price)
            liq_fee = abs(self.position) * liq * LIQUIDATION_FEE
            self.equity = max(0.0, self.equity + loss - liq_fee)
            self.position    = 0.0
            self.entry_price = 0.0
            return True
        return False

    def reset(self):
        self.step_idx       = WINDOW_SIZE
        self.equity         = self.initial_equity
        self.position       = 0.0        # BTC 수량 (양수=LONG, 음수=SHORT)
        self.entry_price    = 0.0
        self._funding_count = 0
        self._trade_cost    = 0.0
        self.done           = False
        return self._get_obs()

    def _get_obs(self) -> np.ndarray:
        """
        관찰 공간 구성:
        [0:295]   log-returns (59 × 5, RevIN 정규화)
        [295:312] account state (17 features)
        """
        idx = self.step_idx
        lr  = self._log_ret[idx - WINDOW_SIZE: idx].copy()
        # RevIN 정규화
        mu  = lr.mean(axis=0, keepdims=True)
        std = lr.std(axis=0, keepdims=True) + 1e-6
        lr_norm = (lr - mu) / std

        close    = float(self.ohlcv[idx, 3])
        mark_p   = close  # 단순화 (실제로는 markPrice API 조회)
        notional = abs(self.position) * mark_p
        fr       = float(self.funding_rates[idx]) if idx < len(self.funding_rates) else 0.0
        upnl     = self.position * (mark_p - self.entry_price) if self.position != 0 else 0.0
        liq_dist = self._liq_distance(mark_p)
        ep_prog  = (idx - WINDOW_SIZE) / max(self.T - WINDOW_SIZE - 1, 1)

        account = np.array([
            float(np.sign(self.position)),               # 0: 방향
            notional / (self.equity + 1e-6),             # 1: 레버리지 비율
            upnl / (self.equity + 1e-6),                 # 2: 미실현손익률
            (self.equity - self.initial_equity) / self.initial_equity,  # 3: 누적수익률
            float(self.position > 0),                    # 4: LONG 여부
            float(self.position < 0),                    # 5: SHORT 여부
            float(self.position == 0),                   # 6: FLAT 여부
            (self.entry_price / (close + 1e-6) - 1.0) if self.position != 0 else 0.0,  # 7: 진입가 대비 현재가
            (FUNDING_INTERVAL_MIN // 15 - self._funding_count) / (FUNDING_INTERVAL_MIN // 15),  # 8: 다음 펀딩까지
            fr,                                          # 9: 현재 펀딩비
            ep_prog,                                     # 10: 에피소드 진행률
            TAKER_FEE,                                   # 11: 수수료율
            liq_dist,                                    # 12: 청산가 거리
            self.equity / self.initial_equity,           # 13: 자본 비율
            notional / (self.equity * self.leverage + 1e-6),  # 14: 실제 레버리지
            float(self._funding_count) / (FUNDING_INTERVAL_MIN // 15),  # 15: 펀딩 카운터
            min(0.0, (self.equity - self.initial_equity) / self.initial_equity),  # 16: 손실 깊이
        ], dtype=np.float32)

        return np.concatenate([lr_norm.flatten(), account])

    def _liq_distance(self, price: float) -> float:
        """청산가까지의 거리 비율 [0,1]"""
        if self.position == 0.0:
            return 1.0
        liq = self.liquidation_price(
            self.entry_price,
            "LONG" if self.position > 0 else "SHORT"
        )
        if self.position > 0:
            dist = (price - liq) / (price + 1e-9)
        else:
            dist = (liq - price) / (price + 1e-9)
        return float(np.clip(dist, 0.0, 1.0))

    def action_to_order(self, action: int) -> tuple:
        """
        이산 행동 → (direction, equity_pct) 변환
        0: FLAT
        1~5: LONG 10%~50%
        6~10: SHORT 10%~50%
        """
        if action == 0:
            return "FLAT", 0.0
        elif 1 <= action <= 5:
            return "LONG", action * 0.10
        elif 6 <= action <= 10:
            return "SHORT", (action - 5) * 0.10
        raise ValueError(f"Invalid action: {action}")

    def step(self, action: int):
        if self.done:
            raise RuntimeError("Call reset() first.")
        self._trade_cost = 0.0

        direction, pct = self.action_to_order(action)
        idx   = self.step_idx
        close = float(self.ohlcv[idx, 3])
        low   = float(self.ohlcv[idx, 2])
        high  = float(self.ohlcv[idx, 1])

        # 1. 펀딩비 정산 (8h 주기, mark price 기준)
        self._apply_funding(idx, mark_price=close)

        prev_equity = self.equity

        # 2. 주문 실행 (Taker 수수료 포함)
        self._execute_order(direction, pct, close)

        # 3. 청산 체크 (Mark Price Low/High 기준)
        liquidated = self._check_liquidation(low, high)

        # 4. 보상 계산 (symlog 스케일)
        equity_change = self.equity - prev_equity
        reward = float(np.sign(equity_change) * np.log1p(abs(equity_change)) * 10.0)
        if self._trade_cost > 0.0:
            reward -= 0.05  # 과잉 거래 페널티

        # 5. 종료 조건
        self.step_idx += 1
        bankrupt = self.equity < self.initial_equity * BANKRUPTCY_BUFFER
        done     = (self.step_idx >= self.T - 1) or bankrupt or liquidated
        self.done = done

        info = {
            'equity':     self.equity,
            'position':   self.position,
            'trade_cost': self._trade_cost,
            'liquidated': liquidated,
            'bankrupt':   bankrupt,
            'step':       idx,
        }
        return self._get_obs(), reward, done, info
```

```python
        내부 direction 변수: "FLAT" / "LONG" / "SHORT" (RL 에이전트 내부 표현)
        Binance API side 파라미터: "BUY" 또는 "SELL" 만 허용 (LONG/SHORT 불가!)

          청산:  LONG 포지션(current_pos > 0) → side="SELL" + reduceOnly="true"

                symbol="BTCUSDT",
                side=side,           # ← "BUY" 또는 "SELL" 만 허용 (LONG/SHORT 금지)

                quantity=abs(current_pos),
                reduceOnly="true"    # ← One-way 모드 전용, Hedge 모드에서는 사용 금지
            )
        elif direction in ("LONG", "SHORT") and pct > 0:

            if current_pos != 0:
                side = "SELL" if current_pos > 0 else "BUY"

                    symbol="BTCUSDT",
                    side=side,           # ← "BUY" 또는 "SELL" 만 허용
                    type="MARKET",
                    quantity=abs(current_pos),
                    reduceOnly="true"

            mark_p   = state['mark_price']

            if qty >= 0.001 and qty * mark_p >= 50.0:  # MIN_NOTIONAL 체크
                # direction="LONG" → side="BUY", direction="SHORT" → side="SELL"

                    symbol="BTCUSDT",
                    side=side,           # ← "BUY" 또는 "SELL" 만 허용 (direction 값 그대로 전달 금지!)
                    type="MARKET",
                    quantity=qty,
                    newOrderRespType="RESULT"
                )
```

```python
def verify_game_rules(client: UMFutures):
    """봇 시작 전 게임 규칙 실시간 검증"""
    # 1. 실제 BTCUSDT 필터 확인
    info = client.exchange_info()

    print(f"tick_size={tick['tickSize']}, step_size={lot['stepSize']}, "
          f"min_notional={notional['notional']}")

    # 2. 현재 레버리지 브라켓 확인
    brackets = client.leverage_brackets(symbol="BTCUSDT")
    b1 = brackets[0]['brackets'][0]
    print(f"Bracket1: MaxLeverage={b1['initialLeverage']}, MMR={b1['maintMarginRatio']}")

    # 3. 펀딩비 cap/floor 확인
    fund_info = client.funding_info()
    btc_fund  = next((x for x in fund_info if x['symbol'] == 'BTCUSDT'), {})
    print(f"FundingCap={btc_fund.get('adjustedFundingRateCap')}, "
          f"FundingFloor={btc_fund.get('adjustedFundingRateFloor')}, "
          f"Interval={btc_fund.get('fundingIntervalHours')}h")
```
