## 1. 사전등록
- 가설, 게이트(G0~G3·G-B·G-F·플라시보), OOS 앵커, 트라이얼 수 N, 임계, 창 길이, 사이징 θ 가족을 **측정 전에** 문서로 확정한다.
- N 카운터로 Bonferroni 보정. 트라이얼을 추가하면 N이 오르고 임계가 올라간다 — "N 무증가"를 주장하려면 그 근거(동일 가설의 전진 검증 등)를 적는다.
- 앵커 시각 증거는 Google Drive **createdTime**(rclone이 로컬 mtime을 보존하므로 modifiedTime은 보조). 로컬 파일 mtime은 다운로드 시각이라 절대 대용하지 않는다.
- 등록 문서에서 벗어난 측정은 프로토콜 위반이고 반드시 공개한다. 결과를 본 뒤 임계·창·게이트를 바꾸는 것은 금지 — 필요하면 새 트라이얼로 등록한다.
- OOS 창 길이는 기대 트레이드 수와 방어할 자기상관 ρ̄에 맞춘다: `n_eff ≥ 30 ⟺ n ≥ 30(1+4ρ̄)`. T1 계열은 창 ≥ 150일.
- **θ = 10 bps는 순 엣지 문턱, MDE > 20 bps(2θ)는 검정력 부족 문턱이다(v1.6 · #96).** 둘을 섞어 "θ = 20"이라 쓰지 않는다. MDE = (z₁₋α + z₀.₈₀)·sd/√(n/1.6), α = 0.05/N(N = 64이면 계수 ≈ 4.0; 3.34는 N = 8 시절 값).
- **앵커 전 검정력 관문(트라이얼 #5부터 · 소급 없음 · #86).** IS 이전 자료의 트레이드 net sd와 투영 n으로 **N 보정 투영 MDE**를 계산해 사전등록에 적고, ≤ 20이 아니면 앵커하지 않는다(창·보유·빈도를 바꾼 새 초안 또는 폐기). 임계는 MDE를 보기 전에 고정한다.
- **P1의 SL 승계 여부**를 귀무의 정의로 명시한다(원판에 SL이 있으면 P1 슬롯이 같은 sl_dist의 SL을 물려받는지 — 기본값 없음, #87·L16). **사이징 가능성 보정**: E_ref·리스크 예산·LOT_SIZE 최소 수량에서 체결 불가능한 sl_dist × 가격 구간과 그 구간에 드는 후보 비율을 IS 이전 보정에 적는다(#88·L15).

## 2. 게이트 순서
G0 이벤트 수/기회 → G1 총 엣지 → G2 비용 차감 순 엣지 → G3 OOS → G-B PSR/DSR(다중검정 보정) → 벤치마크 비교.

- 성과 조건에서 트레이드 0건 = 즉시 FAIL(생존 조건의 N/A와 구분).
- PSR>0.5 **와** n≥30은 각각 필수. DSR>0 단독은 N=1에서 무효.
- 단일자산 6년 표본·현실적 Sharpe에서 t≥3(Harvey-Liu-Zhu)은 구조적으로 불가능 → PSR/DSR + 벤치마크 비교가 올바른 설계다. t≥3 미달을 "실패"로 읽지 않고, 반대로 t≥3 게이트를 새로 넣지도 않는다.
- 비용은 G2에서 들어간다. 비용 모델은 실측 꼬리표(레짐·기간)가 있어야 하고, 이미 판정된 트라이얼을 새 비용값으로 소급 재개봉하지 않는다(민감도상 강건하면 기록만). **단 비용 경로 자체가 바뀐 경우(예: 현물 maker 0 bps 실측)의 사후 재가격은 스크린(§9)으로만 하고, 그 결과는 발견 증거가 아니다**(S-carry-1 선례).
- **가족별 벤치마크는 보고 열이다(v1.6).** carry → FRED DTB3(point-in-time, 보유기간 환산; 창 시작 직전 값은 LOCF 10일 허용) · execution → 결정 시각 즉시 taker 실행가 · directional → vol-targeted 롱온리 BTC. 정식 트라이얼의 벤치마크 **게이트는 P1**(§5)이며 가족별 벤치마크가 이를 대체하지 않는다.

## 3. 플라시보 3층
무작위 타이밍 부트스트랩 · 신호 지연 · 부호 반전. 세 층 전부 필요하다. 플라시보(특히 C2)가 신호를 지배하면 그 자체가 기각 기준이다.

## 4. 판정과 기록
- 3분류: **ACCEPT / REJECT / 폐기**. 기각을 명확히 나눈다 — **검정력 부족**(사후 MDE ≫ 임계, 표본이 답을 못 줌) vs **효과 부재**(MDE ≪ 임계, 답이 "없다"). 후자는 잘 검정된 음성 결과이고 연구 성과로 취급한다.
- **분류 순서(트라이얼 #4부터·소급 없음, #61)**: ① 순 엣지 CI가 **전부 0 아래**면 → **효과 부재(음의 효과)** — MDE와 무관하게 "있다, 음수다"는 답이 나온 것이다 ② 아니면 MDE ≫ 임계 → 검정력 부족 ③ MDE ≪ 임계 → 효과 부재 ④ 그 밖(플라시보 지배 등) → 결론 보류형 REJECT. 트라이얼 #3까지는 ①이 없어 순 CI 전부 음수인 결과가 "검정력 부족"으로 기록됐다.
- **ACCEPT는 전진 단계에서만** 나온다. IS 판정기는 `IS PASS · 생존 통과` / REJECT / 폐기로 끝난다. 판정 문자열은 앵커된 사전등록의 문구를 글자 그대로 쓰고(예: `<라벨>(§7-2: <분류>) · 생존 <통과|실패>`), 암이 둘이면 결과는 쌍(`L: … | S: …`)이며 사전등록이 정의하지 않은 결합 판정을 만들지 않는다.
- 레지스트리는 **append-only**. 틀린 행은 고치지 않고 정정 행을 덧붙인다(행 번호 인용). 승인·조건·검토자·근거를 한 행에 남긴다.
- 실패 후보의 이름만 바꿔 재제안하지 않는다. 새 후보는 레지스트리와 대조하고 "이전 기각과 무엇이 다른가"를 먼저 답한다.
- 판정 뒤 진단 티어시트(quantstats: Sharpe·Sortino·Calmar·MDD·Ulcer·Omega·VaR/CVaR·승률·PF·노출률·몬테카를로)는 **사전등록 판정에 포함하지 않고** 중간보고에도 첨부하지 않는다 — 판정과 진단을 분리한다.
- 각 실패 트라이얼은 사이클 포스트모템을 남기고 구조적 발견을 learnings에 올린 뒤 다음 트라이얼을 설계한다.
- 비핵심 아키텍처 질문은 D-DEFER 시리즈로 등록하고 즉석 결정하지 않는다(스코프 크립 방지).

## 5. 측정 하네스
- **격리 실행**: 정본 전략 코드를 subprocess로 그대로 실행한다. 측정용 재구현은 이탈과 코딩 오류를 숨긴다.
- 비트동일 재현이 종료 게이트에 들어간다(E2E G2). holdout 개봉 횟수를 기록한다(목표 0회).
- 도구 출력은 verbatim으로 붙인다. 재구성된 출력(에이전트가 DB 행을 "복원"한 것 등)은 하드 실패.
- 스키마 변경은 버전 단계가 있는 마이그레이션 도구로만. 절차 이탈은 로그.
- 사이징 θ 가족은 SL의 스케일이 정한다: 15m급 SL → buffer_v2, 4h급 SL → buffer_v3(교차 조건부, c_v3 4.1775×ATR%_4h). 합성 SL-교차법으로 버퍼 보정(q_c=0.9995 @1m).
- E2E 비용 데이터는 `data/e2e_ro/` read-only, `USAGE_SCOPE=cost_calibration_only`. 다른 용도로 쓰지 않는다.
- **통계 평가는 고정 명목**(트레이드당 bps는 규모 무관). 복리는 전진 페이퍼에서만 — 복리 백테스트는 음의 기대값에서 자본이 소진돼 후기 표본을 잃는다(L5).
- **플라시보 P1(노출 매칭 무작위 타이밍)이 곧 벤치마크 게이트다.** B&H Sharpe는 보고만 하고, ACCEPT인데 B&H 미달이면 "ACCEPT — 패시브 미달" 라벨(라이브 전환 결정용, 과학적 판정 아님).
- **P1 관례를 사전확약한다**: 진입 그리드(1m 마감), (sl_dist, 보유시간) 쌍 동시 재표본, 긴 보유부터 배치·쌍 재추출 금지, 창 밖 읽기 금지, RNG(PCG64·SeedSequence spawn·호출 순서)·고정 공개 시드, 실패 draw >1% → DISCARD(REJECT 아님). 같은 시드로 두 구현자가 동일 귀무분포를 내야 한다.
- 평가 스크립트는 **실행 전에 커밋·푸시**(타임스탬프가 결과보다 앞선다는 증거). 모든 출력은 전부 끝난 뒤 한 번에 연다.
- **코드 동결·1회 판정**(트라이얼 #3 이후): 실데이터 캡처 전에 ① 구현 규약 파일 확정 행(SHA256·커밋, 이후 불변) ② 동결 행(판정을 바꿀 수 있는 파일 전부의 매니페스트·지문·H) ③ 판정기 커밋이 origin/main 조상임을 게이트가 확인. 자식 프로세스는 판정기 실행 전까지 트레이드·깔때기 **개수만** 출력한다. 실데이터를 읽은 뒤 어떤 수정도 "실패·수정 행 → Codex 검토 → 새 동결(키에 버전) → 전부 재시작"이며, 판정기가 판정을 냈으면 그 판정으로 닫는다. 게이트 전 실패(rc 8)는 데이터 미접촉·지문 재확인·메모 1행 조건으로 1회 재시작 가능.
- **판정기 요구사항**(트라이얼 #2 이후): B&H 미달 접미사는 ACCEPT에만 붙는다 · 보고 전용 **비용 민감도 그리드**(순엣지 ×0.5/×1.0/×1.5 비용) — "총 엣지 ≈ 비용" 케이스를 한눈에 보이게 · 퇴화 통계(분산 0·n<2)는 어떤 경우에도 통과로 읽지 않는다 · 판정 문자열은 3분류 + 생존을 한 줄로 · 구현 규약(사전등록이 안 정한 선택)은 실데이터 손익 계산 **전에** 레지스트리 행으로.
- **N 카운터는 같은 IS 자료 위의 시도 수를 누적**한다. 이전 트라이얼이 영구 종결됐어도, 그 결과를 보고 고른 새 가설은 N을 올린다("N 무증가"는 동일 가설의 전진 검증에만). 트라이얼 #2는 N=4(α 0.0125 · CI 98.75%).
- **생존 게이트**: 고레버리지 트라이얼은 IS·OOS·전진 각 단계에서 청산 0건을 사전확약한다(1건이면 성과와 무관하게 REJECT).
- **착수 전/후 advisor + Codex 심층토론**은 사전등록·앵커·하네스/엔진 변경·판정기·배포 등 모든 중요 작업의 표준 절차다(2026-09-24 사용자 규칙). 두 패스 모두 verbatim 기록 + 항목별 동의/이견. Codex 사용량 초과면 사후 패스는 대기(앵커 등 되돌릴 수 없는 단계는 그 전에 진행하지 않는다).

## 6. 페이퍼·전진 테스트
- 전진 페이퍼 테스트도 사전등록·앵커한다(창 시작/종료 시각, 서버, 심볼, N 처리). 현행: T1_v2(TSMOM 4h) 2026-09-15 00:00Z ~ 2027-03-14 23:59Z(181일), 도쿄 서버 2, 5심볼, N 무증가.
- 중간보고(30/60/90/120/150일)는 **성과 미표시** — 생존·무결성만. 판정은 창 종료 시 1회.
- 페이퍼는 taker-only·보수 비용으로 체결 시뮬. 라이브 전환은 사용자가 성과 충족을 판단한 뒤, BTCUSDT부터 단계적으로(ETH·XRP는 수집기 buffer_1s θ 확보 후). 페이퍼↔라이브는 언제든 전환 가능하게 구현하되, E2E처럼 실주문 경로가 금지된 저장소에서는 구현 자체를 하지 않는다.
