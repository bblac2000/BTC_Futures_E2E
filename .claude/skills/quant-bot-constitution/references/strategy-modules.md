# 영역 D — 전략 모듈 (사이징 · 평가지표 · 고급 실행 · 지지/저항 · DB 스키마)

사용자 확정(2026-09-12): 레버리지 50~100x 레짐별 동적, 메인 1m 봉, 페이퍼 1개월(도쿄 VPS) 후 사용자 만족 시 라이브. 이 파일은 그 전제 위에서 각 모듈을 어떻게 설계·리뷰하는지 정한다. 모든 값은 config/레짐 함수로 두고 리터럴로 박지 않는다(영역 A 원칙).

## 1. 동적 포지션 사이징

**순서가 핵심이다: SL 거리 → 레버리지 → 수량.** 레버리지를 먼저 고르고 SL을 맞추는 방식(sizing v1)은 기각됐다.

```
risk_usdt     = equity × risk_pct(regime)            # 예 0.5~2%, 레짐 함수
sl_dist_pct   = k(regime) × ATR%(sl_scale)           # SL 스케일의 ATR (1m이면 1m ATR, 15m 컨텍스트면 15m ATR — 실행 스케일과 일치)
L_raw         = risk_pct / sl_dist_pct               # SL에 맞으면 정확히 risk_usdt를 잃는 레버리지
L             = clamp(L_raw, L_min(regime), L_max(regime))   # 사용자 범위 50~100x 안에서 레짐별
liq_dist_pct  = 1/L − MMR(bracket, symbol) − liquidationFee   # 격리·원웨이 근사, 런타임 값
require       sl_dist_pct × buffer(q_c) < liq_dist_pct        # 아니면 L을 낮추거나 진입 금지
notional      = equity × pos_pct(regime) × L         # pos_pct 10~40%
qty           = floor(notional / mark, step) → MIN_NOTIONAL 재확인 → MARKET_LOT maxQty 확인
```

- 100x·tier1 MMR 0.4%면 `liq_dist ≈ 0.6%`. 1m ATR%가 0.05~0.1%면 SL 3~5 ATR ≈ 0.15~0.5%라 버퍼 포함 시 겨우 들어간다. 변동성 레짐에서 ATR%가 커지면 100x는 **자동으로 불가능**해지고 L_raw가 내려간다 — 이것이 "레짐별 동적"의 실제 의미다. 레짐 라벨로 레버리지를 직접 고르는 설계는 반려.
- 브라켓 tier가 바뀌면 MMR과 최대 레버가 바뀐다. 명목이 tier1 캡(BTC 300k)을 넘는 일은 1,000 USDT 자본에선 없지만 코드는 브라켓 조회값을 써야 한다.
- 왕복 비용 ~0.1%(taker×2)+슬리피지가 SL 0.3%의 1/3이다. R:R과 승률 요건을 사전등록에 명시하고, G2에서 비용 차감 후 순엣지가 0 이하이면 1m 스케일에서 그 신호는 기각이다.
- 레짐 정의(추세/횡보/고변동/저변동 등)와 각 레짐의 (risk_pct, k, L_min, L_max, pos_pct)는 config 표로 두고 레짐 판정 지표(ADX, ATR 백분위, 실현변동성 등)는 런타임 계산.

## 2. 평가지표 — 판정용과 진단용을 분리

사용자 목록에서 **판정용(사전등록, 소수)** 과 **진단용(티어시트, 다수)** 을 나눈다. 판정용에 넣는 지표는 임계와 함께 측정 전에 확정하고, 진단용은 결과를 읽는 데만 쓰며 판정에 영향을 주지 않는다.

**판정용 (사전등록 대상, 7개)**
| 지표 | 왜 | 비고 |
|---|---|---|
| 순수익률(비용 차감 후) | G2 | 수수료+슬리피지+펀딩 전부 |
| 트레이드 수 n, n_eff | G0 | n ≥ 30(1+4ρ̄) |
| PSR / DSR | G-B | 다중검정 보정 |
| MDD | 생존 | 청산 거리·킬스위치와 연동 |
| Profit Factor | 거래 특성 | 비용 차감 후 |
| 청산·킬스위치 발동 횟수 | 생존 조건 | 0이 아니면 성과 조건 무효 |
| 벤치마크 대비(BTC 보유·무위험) | 최종 게이트 | |

**진단용 (quantstats 티어시트, 판정 뒤·중간보고 미첨부)**
Sharpe·Sortino·Calmar·Omega·Ulcer·Martin, VaR/CVaR, Recovery Period·Drawdown Duration, Win Rate·Risk-Reward·Exposure/Time in Market, Monte Carlo(부트스트랩 자산곡선), 자산곡선 R², IR, t-stat/p-value.

**뺀 것과 이유**
- Probability of Run(연속 손실 확률)은 Monte Carlo 안에서 나온다 — 별도 지표로 두지 않는다.
- t-stat/p-value는 단일자산 표본에서 t≥3이 구조적으로 불가능하므로(research-protocol §2) 참고값이지 게이트가 아니다.
- Sharpe류는 1m 봉 수익률로 계산하면 자기상관과 비정상성으로 부풀거나 찌그러진다 — 일별 자산곡선으로 계산하고 연율화 기준(√365 vs √252)을 문서에 명시.

quantstats는 진단용 도구로 적합(HTML 리포트·`qs.stats.*`). 판정용 7개는 자체 코드로 계산해 quantstats 값과 대조(두 값이 다르면 정의 차이를 문서화).

## 3. 고급 실행 — 피라미딩·트레일링 스톱·부분익절

헌법 제약이 그대로 적용된다: 전부 **봇 모니터링 + MARKET(청산은 reduceOnly)**. 서버측 STOP/TP/TRAILING은 쓰지 않는다.

**공통 규칙**
- 각 기능은 독립 on/off config이고, 사전등록에 "사용/미사용"이 명시된다. 켜면 별도 트라이얼 또는 A/B(진입조건이 실질적으로 갈려야 의미).
- 각 기능이 낳는 모든 주문은 §1 정규화·MIN_NOTIONAL·MARKET maxQty를 통과해야 한다. **부분익절 잔량과 피라미딩 추가분이 MIN_NOTIONAL 미만이 되는 경우**를 먼저 계산한다(reduceOnly는 면제, 신규 추가는 면제 아님).
- 1m 봉 마감(x=true) 기준 회계와 봉 내(x=false) 즉시 판단을 구분한다. 트레일링·SL은 봉 내 mark 기준으로 즉시, 피라미딩·부분익절 판정은 봉 마감 기준 권장.

**피라미딩**
- 추가 진입은 최대 N회(config), 각 추가분은 초기 수량의 비율(예 50%·25%), 추가는 **미실현 이익이 SL 1단위 이상**일 때만. 추가 후 평균진입가·청산가·총 명목을 재계산하고 §1 `require`를 다시 통과해야 한다 — 100x에서 피라미딩은 청산 거리를 빠르게 잠식하므로 대부분 자동 거부될 것이고, 그게 맞다.
- 총 명목 = 단일 진입의 pos_pct 상한을 넘지 않는다(피라미딩은 진입 분할이지 사이즈 증폭이 아니다).

**트레일링 스톱**
- 봇 내부 상태: `trail_anchor`(최고/최저 mark), `trail_dist`(ATR 배수 또는 %, 레짐 함수). 발동 = mark가 anchor에서 trail_dist만큼 되돌림 → MARKET reduceOnly 전량.
- 활성 조건: 미실현 이익 ≥ 활성 임계(예 1 SL)일 때만 트레일링, 그 전은 고정 SL. 트레일은 유리한 방향으로만 이동.
- 페이퍼 시뮬은 봉 고가/저가로 anchor를 갱신하되 같은 봉에서 SL과 TP가 둘 다 닿으면 **SL 먼저**(보수).

**부분익절**
- 단계 표(예 1R에서 30%, 2R에서 30%, 나머지 트레일링). 각 단계는 reduceOnly MARKET. 첫 부분익절 후 SL을 진입가로 올리는(BE) 규칙은 별도 플래그.
- 잔량이 stepSize 미만이거나 청산 시 MIN_NOTIONAL 면제로 처리 가능한지 확인. 잔량 청산은 항상 `abs(positionAmt)` 전량.

## 4. 지지/저항 수학

지지/저항은 **사전등록 가능한 결정론적 정의**로만 쓴다. "차트에서 보이는 선"은 재현이 안 되므로 금지. 아래 중 어느 것을 쓰든 파라미터를 config에 두고 계산을 DB 컬럼으로 남긴다(§5).

| 방법 | 정의 | 파라미터 | 용도 |
|---|---|---|---|
| 스윙 고/저 (fractal) | `H_t`가 좌우 각 k봉의 고가보다 높으면 저항 후보, 저가 대칭 | k(예 5·10), 유효 기간 | 기본 S/R |
| 피벗 (Classic/Fibonacci/Camarilla) | `P=(H+L+C)/3`, `R1=2P−L`, `S1=2P−H`, `R2=P+(H−L)`, `S2=P−(H−L)`; Fib는 `P±0.382/0.618/1.0×(H−L)` | 기준 기간(전일·전 4h) | 일중 레벨 |
| 돈치안 채널 | `max(H, n)`, `min(L, n)` | n | 돌파·되돌림 레벨 |
| 볼륨 프로파일 | 가격 bin별 거래량 합 → POC(최대 bin), VAH/VAL(POC 중심 70% 거래량 구간) | bin 크기(tick 배수), 창 길이 | 거래량 기반 S/R |
| 가격 밀도(KDE) | 최근 n봉 종가(또는 체결가)의 커널밀도 극대점 | 대역폭 h, n | 통계적 S/R |
| 레벨 강도 | 터치 횟수 × 반등 폭 합 × 최근성 가중(e^{−λΔt}) | λ, 터치 허용폭(ATR 배수) | 레벨 랭킹 |
| 거리 피처 | `(mark − level)/ATR`, `(mark − level)/mark` | — | 신호·SL 배치 입력 |

- 레벨은 **가격 밴드**(±m×ATR)로 다룬다. 점 레벨은 tick 노이즈에 깨진다.
- S/R 기반 SL 배치: SL = 레벨 밖 + 버퍼. 이 SL 거리가 §1의 `sl_dist_pct`로 들어간다 — 즉 S/R이 멀면 레버리지가 자동으로 내려간다.
- 지지/저항 "판단 분석"의 예측력 자체가 가설이다. 사용 전에 G0~G2를 통과해야 하고, 플라시보(레벨을 무작위로 섞은 것)와 비교한다.
- 볼륨 프로파일·KDE는 1m 봉 수집(또는 E2E 틱)에서 계산 가능. 호가 기반 레벨(오더북 벽)은 E2E L2 데이터로만 가능하고 VCB에는 없다.

## 5. DB 스키마 — 기본·고급·커스텀 피처 컬럼

목적은 매매 복기와 가상 시뮬레이션이므로 **판단 시점에 봇이 본 값**을 그대로 저장한다(사후 재계산 값이 아니라).

| 테이블 | 컬럼군 | 예 |
|---|---|---|
| `bars_1m` | 원천 OHLCV + quote vol + taker buy vol + 거래 수, mark/index 종가, 펀딩율, 봉 완성 플래그 | v6 §10 kline 필드 그대로 |
| `features_base` | 이동평균·ATR(각 스케일)·RSI·ADX·실현변동성·거래량 z | 스케일 접미사(`atr_1m`, `atr_15m`) |
| `features_adv` | 레짐 라벨·레짐 확률, S/R 레벨 값·강도·거리(§4), 볼륨 프로파일 POC/VAH/VAL, 상위 스케일 추세 상태, 펀딩 z, OI 변화 | 각 컬럼에 계산 파라미터 버전 |
| `features_custom` | 사용자 정의 — JSON 컬럼 1개 + 스키마 버전 | 스키마 마이그레이션 도구로만 변경 |
| `decisions` | 봉마다 신호·레짐·계산된 L·qty·sl·tp·거부 사유(정규화 실패, MIN_NOTIONAL, 청산 거리 불충족, 킬스위치) | 진입 안 한 이유가 진입한 이유만큼 중요 |
| `orders` | 요청/응답 원문 JSON, side, qty, reduceOnly, 체결가, 수수료, 슬리피지(mark 대비), 에러 code/msg | 페이퍼도 같은 스키마 |
| `positions` | 진입·추가(피라미딩)·부분청산·청산 이벤트, 평균가, 청산가(거래소 값·자체 계산 값 둘 다), 트레일 anchor 이력 | |
| `funding_events`, `account_snapshots` | 정산액, 지갑/마진/가용 잔고 | |
| `runtime_rules` | 기동 시 조회한 tick/step/MIN_NOTIONAL/브라켓/수수료/펀딩 cap 스냅샷 + 조회 시각 | 드리프트 감사·복기 재현용 |

- 모든 피처 컬럼은 `(name, params_version)`으로 추적. 파라미터가 바뀌면 새 컬럼이거나 버전 증가 — 같은 이름에 다른 정의를 덮어쓰지 않는다.
- 페이퍼와 라이브는 같은 스키마에 `mode` 컬럼.
- 스키마 변경은 `tools/migrate_schema.py` 같은 버전 단계 도구로만.

## 6. 스킬이 추가로 요구하는 안전장치 (사용자 요청 외 추가)

- **킬스위치**: 일일 손실 한도(equity의 x%), 연속 손실 n회, 청산 1회 → 신규 진입 중단 + 텔레그램. 재개는 사람이 `/start`.
- **stale-data kill**: 마지막 kline/mark 수신이 T초 이상 지연되면 진입 금지, 포지션은 청산 검토. 웹소켓 재연결 횟수 기록.
- **시계 동기**: `recvWindow` 오류(-1021) 방지를 위해 서버 시간 오프셋을 주기 측정.
- **rate limit 가드**: REQUEST_WEIGHT 2400/분·ORDERS 300/10초 대비 사용량 카운터, 80%에서 폴링 완화.
- **대사(reconcile)**: 봇 내부 포지션 ↔ `positionRisk` ↔ DB `positions`를 봉마다 대조, 불일치 시 진입 금지 + 알림. 페이퍼도 자체 시뮬 상태와 DB를 대조.
- **텔레그램 `/stop`·`/close`** (사용자 확정 2026-09-12): 발신자 ID 화이트리스트 → 현재 포지션·미실현손익과 함께 "정말 청산할까요? [예/아니오]" 인라인 버튼 → 무응답이면 **3초 간격 3회 재전송** → 예: MARKET reduceOnly 전량, 아니오/3회 무응답: 취소 + "청산 안 됨" 통보. 버튼 콜백에는 명령 발행 시각 토큰을 넣어 오래된 버튼이 나중에 눌려 청산되지 않게 한다(예: 60초 만료). 텍스트 명령('중지'·'stop')도 같은 경로. 중요 이벤트 알림(진입·청산·킬스위치·stale-data)에도 같은 3회 규칙을 config로 켤 수 있다.
- **페이퍼 체결 모델**: taker 전용, 봉 내 체결가 = mark 기준 + 보수 슬리피지, 같은 봉 SL/TP 동시 도달은 SL 우선. 실측 슬리피지(0.016 bps, 2026-08 레짐)를 쓰되 꼬리표 유지.
- **라이브 전환 체크리스트**: 격리 확정·레버리지 설정·원웨이 확인·`runtime_rules` 스냅샷·킬스위치 테스트(페이퍼에서 강제 발동)·텔레그램 왕복 테스트·config 해시 레지스트리 기록. 하나라도 빠지면 전환 금지.

## 7. 리뷰 체크리스트
